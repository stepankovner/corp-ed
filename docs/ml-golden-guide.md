# Золотой набор: как писать вопросы

**Для кого:** люди, которые пишут вопросы (Артём, Влад, эксперты клиента).
**Задача:** ТЗ A5, промпт ML-агента 2.1. **Срок:** к 30.09 (крайний — 05.10).

Золотой набор — главное мерило качества: на нём выбираются параметры
поиска (A7), порог отказа (A8) и пишется итоговый отчёт. Синтетические
вопросы годятся только как грубое сито. Поэтому вопросы пишут люди.

## Где лежит

`eval/private/golden.csv` — папка `eval/private/` в git не попадает
(репозиторий публичный). Живые вопросы сотрудников и названия внутренних
документов никогда не кладите в другие места репозитория.

Шаблон — `eval/golden.example.csv`.

## Состав — 40 вопросов

| Сколько | Что | `in_corpus` | `type` |
|---|---|---|---|
| 25 | по документам корпуса, из них **не меньше 5 отрицаний** | `true` | `fact`, `procedure`, `negation`, `comparison` |
| 10 | вне документов — ответа в корпусе нет | `false` | `out_of_corpus` |
| 5 | дословные вопросы из интервью Влада, id `iv01`–`iv05` | как есть | как есть |

Среди 10 вопросов вне корпуса половину сделайте **близкими по теме**
(«размер гранта по программе, которой нет в документах»): далёкие («какая
погода?») отсекаются и так, а на близких ошибается и поиск, и модель.

## Колонки

| Колонка | Что писать | Пример |
|---|---|---|
| `id` | `g01`…, для интервью `iv01`… | `g07` |
| `question` | вопрос так, как его задал бы сотрудник, своими словами | «Можно ли перенести отпуск на следующий год?» |
| `expected_answer` | короткий правильный ответ по документу; для вне корпуса — пусто | «Да, по заявлению и с согласия работодателя» |
| `expected_material` | название документа, где ответ | «Положение об отпусках» |
| `expected_section` | номер или заголовок пункта | «3.2» |
| `in_corpus` | `true` / `false` | `true` |
| `type` | `fact` — факт, число, срок; `procedure` — порядок действий; `negation` — вопрос с ложной предпосылкой или ответ «нет»; `comparison` — сравнение двух вещей; `out_of_corpus` — ответа нет | `negation` |
| `level` | `тема` — вопрос общий, ответ собирается из раздела; `деталь` — про конкретное число, срок, пункт | `деталь` |

`split` не заполнять — его проставит разбиение.

## Как писать хороший вопрос

- **Своими словами, не копией текста документа.** Вопрос, почти дословно
  повторяющий фразу из документа, завышает метрики поиска.
- **Одна мысль — один вопрос.** Для сравнения — тип `comparison`.
- **Отрицания обязательны.** «Можно ли подать заявку на бумаге?» (ответ
  «нет, только в электронном виде») — на таких модель чаще всего
  соглашается с ложной предпосылкой.
- **Эталон короткий и проверяемый:** главное число, срок, условие.
  Подробности — не нужны.
- **Никаких персональных данных** в вопросах (ФИО, телефоны, почта).

## Проверка и разбиение

```bash
python -m eval.datasets eval/private/golden.csv
```

Печатает расхождения с составом ТЗ, дубли вопросов и пропущенные поля.

Когда набор готов и проверен — один раз:

```bash
python -m eval.datasets split eval/private/golden.csv
```

Делит набор 50/50 на `dev` и `holdout`, поровну внутри каждого слоя
(по корпусу или нет × тип × уровень × интервью). Повторно не делит.

**Holdout не открывать до финального прогона (задача 2.6, 11–12.10).**
Все скрипты eval без `--split holdout` берут только dev. Если на holdout
что-то подбирать, итоговые числа будут завышены.

Честно про размер: 20 вопросов в holdout дают доверительный интервал
около ±20 п. п. — значимыми будут только крупные разницы.
