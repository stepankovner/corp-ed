## Средние

### 15. Стоимость и последствия «общего ответа» не измерены на случае (б)

Режим Р1: когда выдержки нашлись, но модель по ним отказала, идёт второй
вызов без выдержек. ML замерял только случай (а) — пустой поиск. Риск:
общий ответ противоречит частично найденным документам компании.

**Что делать.** Замер на золотом наборе (задача ML 2.3/2.4). До него —
пометка и `origin` обязательны, плашка на фронте крупно.

### 16. Пороги полнотекста для отчёта о пробелах не заданы

`classify_miss` различает «в базе нет» и «есть, но вектор промахнулся»
по `ts_rank_cd`, а пороги ML подобрал на другой метрике. Пока
`GAPS_STRONG_FULLTEXT`/`GAPS_EMPTY_FULLTEXT` не заданы, полнотекст в
классификации не участвует: часть `retrieval_miss` попадёт в отчёт как
`gap`, precision ниже замеренных 0,88.

**Что делать.** Подобрать на живых логах после первых недель
эксплуатации (ML).

### 17. Перерасход пула кредитов на границе

Проверка пула без блокировки: параллельные вопросы одной компании могут
перерасходовать пул на число одновременных вопросов. Для 30 мест это
десятки кредитов из 12 600.

**Что делать.** Ничего до появления оплаты сверх лимита; тогда —
резервирование кредита до вызова (`DECISIONS.md`, пул кредитов).

### 18. GitHub Actions закреплены тегом, образ — тегом

Подмена тега action или базового образа — атака на цепочку поставки.
SHA и digest в этой среде снять было нельзя. Dependabot обновляет и то,
и другое; Trivy проверяет образ еженедельно.

**Что делать.** Перевести `uses:` на SHA (Dependabot умеет обновлять
SHA с комментарием версии) и `FROM` на digest при первом обслуживании.

### 19. Regex-маскирование персональных данных неидеально

`mask_pii` (ML) закрывает почту, телефоны, паспорта, карты, СНИЛС и
имена по списку. Редкое имя или фамилия без имени пройдут в `qa_log`
и в промпт подписи кластера.

**Что делать.** Срок хранения `qa_log` 90 дней ограничивает ущерб.
Список имён и правила — расширять по находкам; NER-модель — только если
находок много.

### 20. Ограничитель одновременных запросов к LLM — на процесс

`LLM_MAX_CONCURRENCY` — семафор в памяти процесса. При N воркерах
uvicorn квота каталога делится руками: `10 / N`. Ошибка в расчёте —
429 от провайдера и ретраи.

**Что делать.** Слоты в Redis, как у эмбеддингов, — когда процессов
станет больше одного.

### 21. Redis — точка отказа лимитов и квоты

Без Redis приложение в `production` не стартует (осознанно). При падении
Redis в работе: лимиты входа закрываются (503 на вход), лимиты FAQ и
квота эмбеддингов открываются.

**Что делать.** Redis с рестартом (`unless-stopped`) и алерт на 503 у
`/auth/login`. Кластер Redis — не для MVP.

### 22. Планировщик — cron на хосте

`purge` и `gaps` зависят от crontab, который не в репозитории. Забытый
cron = журнал вопросов, который не удаляется по сроку.

**Что делать.** Пункт чек-листа в `DEPLOY.md`. Сервис-планировщик в
compose — когда задач станет больше двух.

### 23. Нет сквозного теста с настоящим Yandex Cloud

Все тесты — с фейковыми адаптерами; формат ответа провайдера
проверяется на записанных телах. Смена формата API обнаружится в бою.

**Что делать.** Ночной прогон `eval.run_eval e2e` против стенда
(ML) — это и есть такой тест; закрепить в расписании после запуска стенда.

### 27. Фильтр прав в векторном поиске — без индекса и после отбора

`_visible_to` (EXISTS по `material_access`) применяется в том же
запросе, что и `ORDER BY distance LIMIT k`. Пока по `chunks.embedding`
нет ANN-индекса, это точный перебор и результат полный. При появлении
HNSW/IVFFlat фильтр после отбора может вернуть меньше k строк
(документы, невидимые сотруднику, займут места в кандидатах).

**План.** При добавлении индекса — либо `ef_search`/oversampling
(брать 5k кандидатов и фильтровать), либо предварительный список
видимых материалов в запросе. Замерить на живых данных клиента.

### 28. Семантика режима `per_user`: документ живёт, пока его кто-то видит

Документ коннектора `per_user` удаляется, когда после полного обхода
всех активных грантов он не встретился ни в одном листинге. Истёкший
грант (`expired`) тоже не листится: если документ видел только он,
документ уйдёт — и вернётся после повторной авторизации сотрудника
(с повторной загрузкой и индексацией). Это честно по правам, но
стоит эмбеддингов.

**План.** Если на практике гранты истекают часто (короткие токены
Битрикс24 без refresh), держать документ N дней без владельцев вместо
удаления. Решить по логам этапа 2.

### 29. Egress воркера ограничен только кодом

Проверка адресов (`core/outbound.py`) — единственная линия против
SSRF; сетевой политики для контейнера `worker` на стенде нет.
Уязвимость в `httpx`/`httpcore` или ошибка в проверке открыла бы
внутреннюю сеть.

**План.** Правила `nftables`/egress-политика по `DEPLOY.md` § 9a при
развёртывании стенда; проверить `curl` из контейнера до метаданных
облака и до базы мимо приложения.

### 30. Нет OAuth-обмена для режима `per_user`

Этап 1 принимает токены сотрудника готовыми (`PUT
/connectors/{id}/mine`). Настоящий сценарий Битрикс24 — редирект на
портал, код, обмен на пару токенов, обновление по refresh — этап 2.
До него режим `per_user` пригоден только для систем с постоянными
токенами (Яндекс OAuth-токен).

**План.** Этап 2: ручки `GET /connectors/{id}/oauth/start` и
`/oauth/callback` со `state`, привязанным к сессии сотрудника,
обновление токенов адаптером, хранение `expires_at` в гранте.

## Мелкие

### 8. mypy не проверяет тесты

`files = ["src"]`. Тестов стало 790, аргумент «мало тестов» больше не
работает.

**Что делать.** Включить `tests` в mypy с ослабленным режимом (без
`strict`) и разгрести находки отдельным коммитом.

### 10. Аддитивный jitter в backoff

`base_delay * 2^attempt + random.uniform(0, 1)`: доля разброса падает с
ростом номера попытки.

**Что делать.** Множитель `random.uniform(0.5, 1.5)`; переписать
ассерт порядка пауз в тесте.

### 13. Репозиторий публичный

Решение не принималось осознанно. Публичны: код, документация решений,
отчёты ML. Непубличны (`.gitignore`): золотой набор, документы
компаний, ключи. gitleaks в CI проверяет историю.

**Что делать.** Решить: портфолио или закрыть до сертификации. Если
закрывать — CodeQL и gitleaks-action на приватном репозитории требуют
планов GitHub Advanced Security / лицензии gitleaks.

### 24. AGPL-3.0 в зависимостях

`pymupdf` и `pymupdf4llm` (разбор PDF) — AGPL. Решение команды 25.09:
принято. Сервис не распространяется, исходники открыты; риск — при
закрытии репозитория и коммерческой лицензии продукта.

**Что делать.** Пересмотреть при закрытии репозитория: коммерческая
лицензия Artifex или замена парсера.

### 25. Стоимость отчёта о пробелах не ограничена деньгами

До 50 подписей за ночь на компанию, ~0,05 ₽ каждая, — до 2,5 ₽ на
компанию в сутки. Кредиты компании не списываются (работа системы, не
сотрудника).

**Что делать.** Ничего; пункт здесь, чтобы стоимость была видна.

### 26. `Server`-заголовок и версии

uvicorn запущен с `--no-server-header`; reverse proxy может добавить
свой. Проверка — пункт чек-листа `DEPLOY.md`.
