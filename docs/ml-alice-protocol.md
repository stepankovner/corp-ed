# Сравнение с Алисой AI для бизнеса: протокол

**Задача:** ML 4 (01.10–12.10). **Статус:** протокол и шаблон готовы
25.09; ответы собирает человек; оценка — задача 4.3.

## Что сравниваем

Наш ассистент (конфигурация на дату прогона: модель, эмбеддер, порог,
версия промпта — из `docs/ml-report.md`) и Алису AI для бизнеса (Яндекс
360) на **одних и тех же документах и вопросах**.

## Правила

1. **Только публичный демо-корпус** — 6 публичных документов (Положения
   Фонда содействия инновациям, правила акселераторов, документ о
   RAG-подсистеме corp-ed — последний только с согласия Артёма). **Документы
   клиентов в Алису не загружать никогда.**
2. **Вопросы:** демо e2e — 24 по корпусу + 8 вне корпуса; плюс публичная
   часть золотого набора (вопросы по публичным документам, без живых
   вопросов сотрудников).
3. **Каждый вопрос — в новом диалоге Алисы**: контекст прошлых вопросов
   влияет на ответ.
4. **Без браузерной автоматизации.** Публичного API у Алисы AI для бизнеса
   нет (проверено 25.09: страница продукта и документация Яндекс 360 —
   только интерфейс; API AI Studio даёт модели Alice AI LLM, но не продукт
   с базой знаний). Ответы собирает человек.
5. **Дата и версия.** Записать дату, тариф и то, что Алиса пишет о себе в
   интерфейсе (версия / «обновлено»). Выводы формулировать «в нашем тесте
   на публичных документах, <дата>, <версии>».

## Как собрать ответы (для человека)

1. Подключить Алису AI для бизнеса в Яндекс 360 (для новых организаций —
   3 месяца бесплатно, до 31.12.2026; после — 1 199 ₽ в месяц за
   сотрудника).
2. Создать базу знаний и загрузить **ровно** 6 файлов демо-корпуса — те
   же, что у нас (исходные PDF / DOCX).
3. Сгенерировать шаблон:
   ```bash
   python -m eval.alice_compare template --dataset <демо-вопросы.csv> \
       --out eval/private/alice_answers.csv
   ```
4. По каждой строке: новый диалог → вопрос дословно → скопировать ответ
   **целиком** в `answer`; в `source` — на какой документ / фрагмент
   сослалась Алиса (как есть, текстом или ссылкой; «нет» — если ссылки
   нет); в `seconds` — время до полного ответа по секундомеру; в `notes` —
   что заметили (переспросила, отказала, сослалась на интернет).
5. Не править ответы и не задавать уточняющих вопросов.

## Метрики (одинаковые для обеих систем)

| Метрика | Как считаем |
|---|---|
| Верные ответы по корпусу | судья + ручная проверка расхождений, эталон из набора |
| Ложные ответы вне корпуса | ответила по существу на вопрос, ответа на который в документах нет |
| F1 отказа | как в `eval.metrics.refusal_prf` |
| Ссылка есть / нет | по ответу |
| Ссылка корректна | ведёт на документ и раздел, где ответ (ручная проверка) |
| Время ответа | медиана и 95 %: у нас — по логам, у Алисы — секундомер |

95 % CI — бутстреп; значимость — парный перестановочный тест
(`eval.compare`). Незначимую разницу называем шумом.

## Слепая оценка (задача 4.3)

Перед судьёй ответы обеих систем нормализуются: убрать самоназвания
(«Я — Алиса», «ассистент компании»), оформление (Markdown, эмодзи),
ссылки заменить на пометку «ссылка: есть / нет». Судья не знает, чей
ответ. Расхождения судьи и ручной разметки разбирает человек.
