## 1. Этап одной строкой

**pre-MVP собран в коде, MVP не закрыт.** Бэкенд, интерфейс, три
коннектора, отчёт о пробелах, учёт лимита и настройки поиска (проверены
ML на золотом наборе) — в `main`. Живьём проверены сквозной ответ с
настоящей моделью Yandex Cloud (28.09, 9 из 9 шагов), боевой прогон
поставки в тестовой среде (28.09) и диск Битрикс24 (26.09).

До MVP осталось четыре вещи:
1. поднять стенд `stage.krontoai.ru` (сервер описан в `STAGE.md`, по
   досье v3.3 ещё не арендован);
2. пройти живые проверки коннекторов, а что не проверим — скрыть из
   каталога;
3. закрыть решения из раздела 6 и встроить их (память диалога, режим
   «ответа нет», лимит);
4. финальный замер ML на закрытых вопросах 11–12.10, отчёт 13.10.

**Цель:** стенд с живым демо к ~14.10, MVP — к середине октября.

## 2. Как позиционируем продукт

**Одной фразой.** kronto — ассистент по внутренним документам и
рабочим системам компании: сотрудник спрашивает обычными словами и
получает ответ со ссылкой на документ и раздел.

**Что можем подтвердить уже сейчас:**

| Отличие | Чем подтверждено | Оговорка |
|---|---|---|
| Ответ со ссылкой на документ и раздел, для системы — на оригинал | в коде; ссылки проверены ML | ссылка на оригинал из подключённой системы живьём не проверена |
| Несколько систем сразу, права повторяются из систем | адаптеры Битрикс24, Confluence Server/DC, Яндекс 360 + загрузка файлов | живьём — только диск Битрикс24 |
| Отчёт о пробелах: каких документов не хватает | ночная задача и экран администратора | на живых вопросах не запускался |
| Быстрее Алисы AI для бизнеса | медиана 0,8 с против 6,2 с, правильность неразличима (тест 26.09, 58 вопросов, `ml-vs-alice.md`) | вторая часть теста — после 12.10 |
| Открытая цена | 990 ₽ за место, первый месяц пилота бесплатно, подключения не тарифицируются (досье 10) | на странице тарифов в коде ещё 1 490 ₽ |
| Данные в России | модели Yandex Cloud, сервер в РФ | ❗ Яндекс по умолчанию сохраняет запросы для улучшения сервиса — заголовок отказа не передаётся (раздел 6, Р-3) |

**Когда ответа в документах нет** — ⏳ решение Р1 (раздел 6). По
решению Артёма 29.09: пометка «В документах компании ответа нет» и ответ
по общим знаниям. В досье v3.3 и в коде — честный отказ.

**Чего не говорим:** «точнее Алисы» (тест этого не показал),
«соответствуем 152-ФЗ» (до юриста — «данные хранятся в России»),
«умеет всё, что умеет любая LLM» (в MVP — вопрос-ответ), «запуск за дни».

**Что в MVP, а что после:**

| В MVP | После MVP |
|---|---|
| Вопрос-ответ по документам со ссылками | Сводка документа, тексты по документам (ML-1, сразу после 13.10) |
| Уточняющие вопросы в диалоге («а для УМНИК?») | Поиск в интернете по кнопке (решения нет) |
| Файлы docx, PDF с текстом, txt, md; ⏳ .doc и .pptx (Р-5) | Сканы (OCR), .xlsx, сетевые папки, обход порталов |
| Битрикс24, Яндекс 360, Confluence Server/DC — что проверено живьём | Боты в мессенджерах, встраивание в портал |
| Отчёт о пробелах, словарь сокращений, лимит | Оплата и счета, самостоятельная регистрация компании |

## 7. Как не расходиться дальше

Недопонимание 28–29.09 выросло из того, что одно решение принимали в
разных разговорах и записывали в разные места:

| Дата | Решение про «ответа нет» | Кто | Где записано |
|---|---|---|---|
| 25.09 | общий ответ с пометкой по умолчанию | Артём (разговор с ML) | `ml-report.md`, `backend-handoff.md` |
| 28.09 | честный отказ по умолчанию | «владелец продукта» (разговор с бэкендом) | `DECISIONS.md`, досье v3.3 |
| 29.09 | снова общий ответ с пометкой | Артём (разговор с ML) | PR #31 — ждёт подтверждения |

Предложение:
1. **Решение о том, что видит клиент** (режимы ответа, цены, лимиты,
   форматы, что в MVP), принимает команда, а не один разговор с
   агентом. Оно записывается в журнал ниже с датой и именем и только
   потом уходит в код.
2. **Агент, который получил указание вразрез с досье или журналом**,
   не выполняет его молча: пишет вопрос в `OPEN-QUESTIONS.md` и называет
   расхождение.
3. **Где что лежит:** продукт и деньги — досье; технические решения
   бэкенда — `DECISIONS.md`; ML — `ml-report.md`; задачи ML для бэкенда —
   только пункты BH в `backend-handoff.md`; открытые вопросы —
   `OPEN-QUESTIONS.md`; этап и план — этот файл.
