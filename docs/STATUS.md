**Продукт собран и работает на стенде, MVP не закрыт.** Все 11 этапов ТЗ
после MVP сделаны к 04.10. С 04.10 по 13.10 добавлены:

  - BH-42 — исправление тестовой модели;
  - BH-43 — второй шаг поиска для ответа из двух документов.

Код ждёт не разработки, а ручных шагов на стенде, живых проверок
подключений и нескольких решений владельца (раздел 3).

**До MVP — пять вещей:**
1. Включить реранкер на стенде.
2. Заново загрузить PDF тестовых компаний и переиндексировать стенд.
3. Живые проверки Битрикс24 (вход сотрудника, базы знаний) и
   Яндекс 360. Что не проверим — скрыть.
4. Включить автовозобновление стенда.
5. Этап безопасности.

**К первому пилоту** нужны ещё:
- непрерываемый сервер и переезд на krontoai.ru;
- копия бэкапа вне сервера;
- правила исходящих соединений;
- уведомление в РКН.

### 3.5. Технический долг

- **Масштаб:** индекс по вектору и фильтр прав — когда у компании будет больше ~50 тыс. фрагментов (№27); ограничитель запросов к модели — в Redis, а не на процесс (№20).
- **Кредиты:** резервировать кредит до вызова модели, когда появится оплата сверх лимита (№17).
- **Подключения:**
  - токены Битрикс24, WebDAV-систем и Kaiten не отзываются у провайдера (№65, №70);
  - дубли в индексе (№69, №75);
  - режим `per_user` — сколько держать документ без владельцев (№28).
- **Качество:**
  - пороги отчёта о пробелах — по живым логам (№16);
  - нет регулярного прогона с настоящим Yandex Cloud (№23);
  - золотой набор не прогнан через интерфейс стенда (№45).
- **Процесс:** mypy не проверяет тесты (№8); cron на боевом сервере ставится руками (№22).
- **Документы, которые отстали:**
  - `OPEN-QUESTIONS.md`: Р-15 решён 06.10; репозиторий остаётся открытым до пилота (решение 10.10);
