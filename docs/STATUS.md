## 3. Что работает сейчас

Пометка «живо» означает проверку на стенде или с настоящей внешней системой,
«тесты» — только автотесты с поддельными провайдерами.

**Компании и люди.** Компанию заводит команда через CLI (код, название,
места, почта админа), временный пароль показывается один раз; приостановка и
возобновление, смена мест и режима «ответа нет». Админ создаёт сотрудников,
меняет роли, сбрасывает пароли; последнего админа понизить нельзя. Вход по
коду компании, почте и паролю; с временным паролем доступна только смена
пароля. Живо: создание компании, вход, смена пароля (стенд этапа 1).

**Документы файлом.** docx, pdf с текстовым слоем, txt, md до 25 МБ; формат
по сигнатуре, защита от zip-бомбы, шифрованные PDF и сканы отклоняются с
понятным сообщением; разбор в изолированном процессе с лимитами памяти и
CPU; оригинал не хранится. Фоновая индексация с очередью в Postgres и общей
квотой эмбеддингов в Redis. Живо: разбор docx и pdf (стенд этапа 1, живой
тест Битрикс24 на PDF в 49 и 85 страниц). Индексация с настоящим Yandex Cloud
живо не проверена — нет ключей в среде.

**Вопросы и ответы.** Сотрудник задаёт вопрос, получает ответ с источниками
(документ, раздел, фрагмент, ссылка на документ в системе компании, если он
пришёл из коннектора) и признаком происхождения: по документам, из общих
знаний, отказ. Если в документах ответа нет — общий ответ с обязательной
первой строкой-пометкой, либо строгий отказ, если компания так настроена.
Оценка ответа 👍/👎. Админу доступна диагностика (модель, версия промпта,
токены, кредиты). Тесты; сквозной ответ через API с настоящим провайдером не
прогонялся (RISKS №23), качество модели и промпта ML мерил своим стендом
напрямую.

**Кредиты.** Пул компании: места × 420 кредитов в месяц, 1 кредит = 2 000
токенов; проверка до платных вызовов, при исчерпании 402 для всех, включая
админа; события аудита на 80 и 100 %; отчёт `GET /usage`. Числа —
предложение досье, не утверждены. Тесты.

**Отчёт о пробелах.** Ночная задача кластеризует вопросы без ответа,
считает приоритет, подписывает кластеры моделью; админ видит список и меняет
статусы, статусы переживают пересборку. Тесты и синтетика ML; на живых
логах не запускался.

**Словарь сокращений.** Админ ведёт расшифровки; они дописываются к вопросу
только для поиска, в промпт не попадают. Тесты.

**Коннекторы.** Каталог из трёх видов: Битрикс24 (диск, личный диск, база
знаний, база знаний 2.0), Confluence Server/DC (страницы, вложения), Яндекс
360 (Диск). Админ создаёт подключение, задаёт секрет приложения или
служебную учётку, проверяет, запускает синхронизацию, смотрит журнал
запусков. Сотрудник видит свои подключения и авторизует приложение через
OAuth. Документы из систем становятся обычными материалами со ссылкой на
оригинал; права: для Confluence — из ограничений чтения, для Битрикс24 и
Яндекса — документ виден тем, у кого он есть в листинге. Оговорка для
Confluence: права пространства через REST не читаются, страницы без
ограничений видит вся компания, поэтому за список пространств отвечает
админ; почта сотрудника выводится из логина по шаблону, при несовпадении
документ никто не увидит (RISKS №37). Синхронизация по расписанию (60 минут
по умолчанию) и по кнопке, с бюджетом на запуск. Живо: API и планировщик на
стенде этапа 1; Битрикс24 по вебхуку на тестовом портале (диск, скачивание,
синхронизация). Не проверено живо: OAuth сотрудника, база знаний,
Confluence, Яндекс Диск, ответ со ссылкой на документ из источника.

**Безопасность.** Изоляция компаний в три кольца (ORM, явные фильтры, RLS с
FORCE; приложение под ролью без обхода RLS), аутентификация по RFC 9700,
периметр (заголовки, TrustedHost, CORS по списку, лимиты тела, 422 без эха),
аудит только на дописывание, сроки хранения и `cli purge`, секреты
источников шифрованы, защита от SSRF, песочница разбора, закреплённая
цепочка поставки. Полностью — `SECURITY.md` с картой мер и чек-листом
пентеста. Живо: RLS под ролью приложения на стенде этапа 1.

**Поставка (стенда пока нет).** Собран один образ в четырёх ролях (api,
worker, migrate, CLI); нужны Postgres с pgvector, Redis, reverse proxy с TLS
перед API, cron на хосте для purge и отчёта о пробелах. Чек-лист —
`DEPLOY.md`. Ни один стенд не развёрнут — п. 6.6.

   1.28, разбор в 5 раз дороже по CPU при том же объёме текста, бюджет
   синхронизации 20 минут на 200 документов не выполняется. Оставить или
   отключить одной строкой; сравнение качества чанков на золотом наборе
   предлагаем поручить ML — с ML не согласовано.
5. **Тестовые системы**: Confluence Server/DC со служебной учёткой и PAT;
   организация Яндекс 360 с OAuth-приложением; доступ к документации
   Atlassian и Яндекса в сетевой политике.
6. **Стенд** с `ENVIRONMENT=production`, ключами Yandex Cloud и
   `CONNECTOR_SECRETS_KEYS`; на нём тестовая компания с шестью файлами
   демо-корпуса и учётка `ADMIN` — ML гоняет eval против живого API.
7. **Просьбы ML**: разрешение скачать модель реранкера (M3, 1–2 ГБ);
   согласие на загрузку документа «RAG-подсистема» в Алису AI для сравнения;
   обновить досье v3.2 под Р1 (общий ответ с пометкой, строгий отказ —
   настройка компании); утвердить формулу приоритета пробелов.
8. **Решения продукта**: числа кредитов (420 на место, 2 000 токенов);
   нужна ли «База знаний 2.0» в MVP; канал уведомлений (остановка
   коннектора, неподключённый источник, 80/100 % кредитов); публичность
   репозитория (RISKS №13); включать ли ответ с дословной цитатой ради
   точности ссылок (в исследовании ML на 242 вопросах — 0,2–0,6 % неверных
   ссылок вместо ~5 %, но p95 13 с против 5 с в тех же условиях; в
   продуктовой конфигурации p95 обычного ответа 2,0 с); запрещать ли в общем
   ответе точные суммы и сроки; форматы .doc и .pptx (в досье «по спросу»,
   решения нет); MFA и восстановление пароля по почте не сделаны (пароль
   сбрасывает админ) — подтвердить, что для MVP это допустимо.
9. **Подтвердить реализованное по предложению** (в `DECISIONS.md` записи
   решения команды нет): удаление подключения стирает его документы и ответы
   по ним сразу; интервал синхронизации 60 минут по умолчанию; при 100 %
   кредитов останавливается и админ; уменьшение мест ниже потраченного
   останавливает компанию до конца месяца.
