## 2026-09-04 — Один HTTP-клиент на приложение

**Контекст.** Адаптер к Яндексу держит пул соединений. Нужны разные политики
ретраев и таймаутов для FAQ и генерации программ.

**Решение.** Один `httpx.AsyncClient` создаётся в `lifespan`, живёт в
`app.state`. Адаптеры получают его в конструктор и не владеют им.

**Альтернативы.**
- Адаптер сам создаёт клиент — проще, но при двух политиках получаем два пула
- Новый клиент на каждый запрос — теряется переиспользование соединений

**Цена.** Ответственность за закрытие уехала в `lifespan`. Заголовок с ключом
переехал из клиента в каждый запрос. Конструктор адаптера вырос до семи
аргументов.

**Статус.** Действует.


## 2026-09-06 - Инфраструктура тестов

**Контекст.** В pyproject.toml добавляется секция `tool.pytest.ini_options`
c настройкой `asyncio_mode`. Нужно решить ее значение: `strict`(дефолт) или `auto`.

**Решение.** Выбираем `auto`, теперь любой `async def test_*` подхватывается сам.

**Альтернативы.**
- Задать значение `strict` - явно видно, что тест асинхронный, но при этом если забыть декоратор,
то тест просто выполнится и будет зеленым.

**Цена.** Неявность. Механизм невидим в коде теста.

**Статус.** Действует.


## 2026-09-06 - Область работы mypy

**Контекст.** В `pyproject.toml` стоит `files = ["src"]` — mypy на `tests/` не смотрит вообще. То есть весь тестовый код вне статической проверки.

**Решение.** mypy только на `src`. Тесты пишутся быстро, без возни с типами моков и фикстур

**Альтернативы.**
- mypy на `src + tests` - ошибки в самих тестах тоже ловятся.

**Цена.** Сломанный тест может молча ничего не проверять

**Статус.** Действует. Временное решение, пока не набралось достаточно тестов для оправданного выбора
альтернативы
