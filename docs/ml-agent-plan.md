# Агент с инструментом поиска (вариант 1) — план

20.10.2026, ML. Решение Артёма 20.10: вариант 3 («не вопрос» в общем
ответе, BH-45) — базовый сейчас, **вариант 1 — приоритет**, ближайшая
крупная задача. Здесь — насколько это сложно, что потребуется, в каком
порядке и что решить.

## 1. Зачем

Сейчас ответ — жёсткий конвейер: любое сообщение → поиск → модель по
выдержкам → при отказе общий ответ. Из этого растут три известные
проблемы, и все три агент закрывает одним механизмом:

| Проблема | Сейчас | В агенте |
|---|---|---|
| «Привет» → «в документах ответа нет» | правило в общем ответе (BH-45) | модель отвечает сама, поиск не нужен |
| ответ из двух документов (должность → имя) | один добор «Дополнительный поиск» (BH-43), 5 из 10 | модель ищет столько раз, сколько нужно (в пределах лимита) |
| вопрос из двух частей, уточнение у сотрудника | нет | несколько поисков; при неясности — уточняющий вопрос |

## 2. Что уже проверено (20.10)

Вызов инструмента `search_documents(query)` через OpenAI-совместимый API
(`sandbox/stand/tool_calling_probe.py`, ≈ 1 ₽):

| | Вопрос по документам | «Привет» | Поток |
|---|---|---|---|
| Яндекс Flash | `tool_calls`, 1,4 с | отвечает сам | `tool_calls` одной частью |
| Cloud.ru gpt-oss-120b | `tool_calls`, 1,8 с | отвечает сам | частями |
| MWS gpt-oss-120b | `tool_calls`, 1,3 с | отвечает сам | частями |

Своего формата вызова изобретать не нужно — у всех трёх звеньев цепочки
резерва стандартный `tools`. Это снимает самый дорогой риск.

## 3. Архитектура — два варианта

**А. Классический агент.** Модель получает сообщение и инструмент, сама
решает, искать ли и что. Плюсы — проще всего, естественный small talk.
Минусы:
- **модель может не искать и ответить «из головы»** на вопрос о компании
  — уверенно и неверно; ровно с этим мы боролись (x03 «Старт-ИИ-2»);
- **+1 вызов модели перед каждым поиском**: 1,3–1,8 с (замер выше) к
  каждому вопросу по документам.

**Б. Сначала поиск, инструмент — для добора (рекомендую).** Как сейчас,
поиск по сообщению идёт сразу (≈ 0,2 с); модель получает выдержки **и**
инструмент. Дальше она:
- отвечает по выдержкам (как сейчас — один вызов, задержки не прибавилось);
- ищет ещё (`search_documents`), если выдержек мало, — обобщение BH-43;
- на «привет» отвечает сама, выдержки игнорирует;
- при неясном вопросе — переспрашивает.

Опора на документы сохраняется: модель всегда видит, что нашлось, и
правило «отвечай только по выдержкам» остаётся. Задержка — как сейчас,
кроме вопросов, где нужен добор.

## 4. Что потребуется

**ML (≈ 6–8 рабочих дней):**
1. Промпт `agent-v1`: правила ответа по выдержкам (из faq-v2.9), когда
   искать ещё, когда отвечать самому, когда переспрашивать; описание
   инструмента; общий ответ с пометкой — как сейчас.
2. Чистые функции (`domain/agent.py`): политика цикла — не больше N
   вызовов инструмента (2–3), без повтора того же запроса, бюджет токенов
   выдержек, нумерация `[n]` через все поиски (новые — после прежних, как
   в BH-43), разбор ответа модели.
3. Eval: `offline_e2e --agent` — цикл с поиском на стенде, журнал шагов
   (что искала, сколько раз, что добавилось); метрики траекторий: доля
   вопросов с добором, «искала ли, когда надо», «не ушла ли от выдержек».
4. Наборы: dev и стенд (как сейчас), «два документа» (10), «не вопросы»
   (46), вопросы вне документов (50) и **соседние программы** (x03-тип —
   нужен расширенный набор, 15–20 вопросов: это главный риск), длинные.
5. Протокол до прогонов и 2–3 раунда замера: Flash и gpt-oss (резерв),
   судья на dev. ≈ 150–300 ₽ (судья ≈ 1,2 ₽ за вердикт).
6. Контракт для бэкенда (BH), handoff.

**Бэкенд (≈ 6–10 рабочих дней):**
1. Цикл в `faq_service`: вызов модели с `tools` → `tool_calls` →
   поиск (тот же путь: права, порог BH-37, реранкер) → вызов снова; лимиты
   шагов и времени.
2. Поток: ответ модели может начаться вызовом инструмента — поток
   придерживать до первого содержательного куска (как `_SearchGate`);
   этапы в чате «Ищу в документах…».
3. `qa_log`: каждый шаг — запрос, найденное, токены, поставщик; кредиты —
   сумма вызовов.
4. `FallbackGateway`: инструменты у всех звеньев (проверено), но формат
   потока разный (Flash — одной частью, gpt-oss — частями, `\u`-экраны) —
   разбирать общим кодом.
5. Фронт: этапы, источники из нескольких поисков, уточняющий вопрос.
6. Выключатель: агент и нынешний конвейер рядом, переключение настройкой;
   BH-43 и BH-45 остаются запасным путём.

**Итого:** ≈ 2–3 недели календарно (ML и бэкенд частично параллельно),
≈ 150–300 ₽ на замеры у Яндекса; у Cloud.ru и MWS — копейки.

## 6. Риски

| Риск | Что делать |
|---|---|
| Модель не ищет и отвечает «из головы» | архитектура Б (поиск всегда); метрика в eval; набор соседних программ |
| Отказ на «соседней» программе ломается (x03 хрупок к любым правкам промпта) | отдельный критерий 100 % на расширенном наборе; без него не включать |
| Задержка | Б: добор — только когда нужен; лимит шагов 2–3; таймаут на шаг |
| Цена (каждый добор — +вызов, ×1,5–2,5 входящих токенов) | лимит шагов, бюджет выдержек; на gpt-oss у Cloud.ru — копейки |
| Зацикливание, одинаковые запросы | политика цикла в чистых функциях ML, тесты |
| Текст документов управляет моделью (prompt injection через выдержки) | инструмент только на чтение; выдержки объявлены данными (как сейчас); лимит шагов |
| Разное поведение поставщиков | замер на Flash и gpt-oss; разбор потока — общий код |
| Недетерминизм — трудно сравнивать | 3 повтора на ключевых вопросах, как с x03 |

## 7. Решения (Артём, 20.10)

1. **Архитектура — Б:** сначала поиск, как сейчас; модель видит выдержки
   и может искать ещё, ответить сама или переспросить.
2. **Доборов — не больше 2** на вопрос.
3. **Уточняющие вопросы — вторым шагом**, после замера агента.
4. **Кредиты — по токенам с потолком** (например, не больше 3 кредитов за
   ответ; потолок — Влад и Артём).
5. **Строгий режим:** реплики («привет», «спасибо») разрешены, вопросы вне
   документов — отказ. Проверить отдельно, нет ли проблем (в наборе
   прототипа — строгий режим).
6. **Сотруднику — только этап «Ищу в документах…»**, без текста запроса;
   запросы — в журнале и отчёте о пробелах. Пересмотреть по опыту.
7. **Критерии переключения — приняты:** стенд ≥ 118 из 140; «два
   документа» > 5 из 10; вне документов 45 из 45 с пометкой; соседние
   программы (расширенный набор, 15–20) — 100 % отказ; dev по судье — не
   хуже; p95 — не больше нынешнего + 2 с; цена — не больше ×1,5.
8. **Начинать сейчас:** ML-прототип в eval (продукт не трогает); бэкенд —
   после пунктов, критичных для MVP (реранкер, повторная загрузка PDF,
   BH-45).
9. **Модели — все звенья:** Flash, gpt-oss у Cloud.ru и у MWS.
10. **Бюджет замеров — 150–300 ₽**; больше 300 ₽ — смета заранее.
11. **BH-45 — бэкенду сейчас**; после агента — запасной путь.

Перед началом работы — изучить курс Яндекса о построении агентов
(плейлист от Артёма) и проверенные статьи; лучшие практики — в раздел 8.
