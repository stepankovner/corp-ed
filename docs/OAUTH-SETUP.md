# Приложения для подключений: Яндекс 360 и Битрикс24

Инструкция для владельца и для администратора компании-клиента (ТЗ §13).
Нужна, чтобы сотрудники подключали **свои** аккаунты Яндекс 360 и
Битрикс24 и ассистент искал по их файлам.

Схема у обоих источников одна:

1. Администратор регистрирует приложение на стороне источника.
2. Код и секрет приложения он вписывает в kronto: «Управление → Источники
   → Подключения → Добавить подключение». Секрет вводится **только в
   форму kronto**: там он хранится зашифрованным. В чат, почту и
   мессенджеры его не отправлять.
3. Каждый сотрудник нажимает «Подключить» в «Настройки → Мои
   подключения». После этого kronto видит в источнике только то, что
   доступно этому сотруднику.

Адрес возврата (Redirect URI) для стенда:

```
https://stage.krontoai.ru/api/v1/connectors/oauth/callback
```

На боевом сервере вместо `stage.krontoai.ru` будет его домен. Точный
адрес форма подключения в kronto показывает сама, рядом с кнопкой
«Скопировать адрес».

Названия пунктов меню у Яндекса и Битрикс24 со временем меняются. Если
пункт называется немного иначе, ориентируйтесь на смысл шага.

## Яндекс 360 (Диск и Вики)

**Кто делает:** любой сотрудник организации с рабочим аккаунтом Яндекса.
Для общих дисков и Вики нужен ещё ID организации — его видит
администратор Яндекс 360.

1. Откройте https://oauth.yandex.ru и войдите **рабочим** аккаунтом, не
   личным.
2. «Создать приложение».
   - Название: `kronto`. Его сотрудники увидят на экране согласия.
   - Платформа: «Веб-сервисы».
   - Redirect URI: адрес возврата выше.
3. Права (доступы):
   - Яндекс Диск REST API → «Чтение всего Диска» (`cloud_api:disk.read`)
     и «Доступ к информации о Диске» (`cloud_api:disk.info`);
   - Яндекс Вики → «Чтение» (`wiki:read`). Можно не включать, если Вики
     не нужна.
4. Сохраните. На странице приложения появятся **ClientID** и **Client
   secret**.
5. ID организации (для общих дисков и Вики): https://admin.yandex.ru →
   «Профиль организации» → число в поле ID.
6. В kronto: «Источники → Подключения → Добавить подключение → Яндекс
   360».
   - ClientID — в поле «ClientID приложения Яндекс ID».
   - Client secret — в поле секрета.
   - ID организации — если нужны общие диски или Вики.
   - Модули: Диск сотрудника, общие диски, Вики.
7. Проверка: сотрудник открывает «Настройки → Мои подключения», нажимает
   «Подключить» и соглашается на экране Яндекса. Его документы
   появляются в ответах после ближайшей синхронизации, обычно в течение
   часа. Администратор видит в «Подключениях» строку «Подключились N из
   M».

## Битрикс24

**Кто делает:** администратор портала Битрикс24 компании-клиента.
Приложение создаётся **на каждом портале** («локальное приложение»).
Партнёрский кабинет Битрикс24 для этого не нужен: он понадобится, только
если публиковать kronto в Маркете Битрикс24 как одно приложение для всех
порталов. Это решение на потом.

1. На портале: «Приложения» → «Разработчикам» → «Другое» → «Локальное
   приложение».
2. Заполните:
   - тип — серверное; отметка «Приложение использует только API»;
   - «Путь вашего обработчика»: адрес возврата выше;
   - «Путь для первоначальной установки»: тот же адрес, если поле
     обязательное;
   - название: `kronto`;
   - права: «Диск» (`disk`) и «Сайты и магазины» (`landing`, через него
     читается база знаний).
3. Сохраните. Появятся **Код приложения (client_id)** и **Ключ
   приложения (client_secret)**.
4. В kronto: «Источники → Подключения → Добавить подключение →
   Битрикс24».
   - Адрес портала: `https://ваш-портал.bitrix24.ru/`.
   - client_id и client_secret — в соответствующие поля.
5. Проверка: как у Яндекса — сотрудник подключает свой аккаунт в «Мои
   подключения».

## Если не получилось

| Что видит сотрудник | Что проверить |
|---|---|
| «Не удалось подключить» сразу после экрана согласия | Redirect URI в приложении совпадает с адресом из формы kronto символ в символ, с `https://` и без `/` в конце |
| Экран Яндекса просит войти личным аккаунтом | Выйти из личного Яндекса в этом браузере или открыть окно инкогнито |
| «Вы отказались дать доступ» | Сотрудник нажал «Отмена» на экране согласия — достаточно подключить ещё раз |
| Подключение «доступ истёк» | Токен отозван в Яндексе или Битрикс24 — нажать «Подключить заново» |
| Документов нет в ответах через час | «Источники → Подключения → подключение»: статус последней синхронизации и ошибка, если есть |

Сетевые требования сервера (какие адреса Яндекса и Битрикс24 должны быть
доступны) — в `DEPLOY.md`, раздел 9a.
