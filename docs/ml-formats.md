# Форматы файлов: качество по каждому (Р-5)

**Решение Артёма 29.09 (Р-5):** форматы .xlsx, .pptx, .doc — сейчас, **по
одному**. Следующий формат — только когда предыдущий дошёл до приемлемого
качества на тестах; статистика — по каждому формату; если на живых данных
качество упадёт — формат выключается настройкой. Порядок (предложение ML):
.xlsx → .pptx → .doc.

Здесь — критерии, итоги по каждому формату и как повторить замер. Решения
продукта — в `ROADMAP.md`, задачи бэкенду — в `backend-handoff.md` (BH-33
для .xlsx), подробности замеров — в `ml-report.md`.

## Критерии приёмки формата

Формат принят ML, если на наборе вымышленных документов этого формата и
том же содержании в .docx (текущий путь продукта):

1. **Текст:** ≥ 95 % значений ячеек и абзацев есть в тексте после
   `preprocess`.
2. **Ключи таблиц:** у строк таблиц сохраняется шапка — «ключ: значение»
   в той же строке, что подпись строки.
3. **Поиск и ответы не хуже .docx** в пределах шума (`eval.compare`,
   правило отчёта: «лучше / хуже» — только если CI без нуля и p < 0,05).
4. **Не портит остальное:** поиск по золотому dev с новыми файлами в
   корпусе не меняется; вне документов новых ответов по чужим выдержкам нет.

## .xlsx (01.10)

**Код.** `src/corp_ed/ingest/xlsx.py` — без сторонних библиотек (`zipfile`
и потоковый `xml.etree.iterparse`): образ бэкенда не меняется, лист
читается потоком. Как книга становится Markdown — в docstring модуля и
`ml-code-guide.md`, 3.11. Коротко: лист — заголовок `#`, короткий текст
над таблицей — её заголовок, объединённые ячейки размножаются, шапка в
две строки склеивается («Суточные — до 10 дней»), строка-группа
(«Россия», «Бухгалтерия») — подзаголовок, значения — как их показывает
Excel. Скрытые листы пропускаются, скрытые строки — нет (автофильтр).
20 тестов (`tests/ingest/test_xlsx.py`), включая zip-бомбу, `<!DOCTYPE>`,
книгу с паролем и потолок числа ячеек; +1 тест загрузчика стенда.

**Набор.** Пять вымышленных книг ООО «Пример» — нормы командировочных
расходов (три листа, шапка в две строки, группы, объединения по
вертикали), справочник контактов (группы-отделы), план адаптации (даты,
время, да/нет, проценты), льготы (проценты, рубли, скрытый лист, формула),
матрица согласования договоров (примечание под таблицей). Документы
написаны ML, клиентских данных нет. 25 вопросов (24 по таблицам, 1 вне
документов) — черновик ML, только dev (`eval/private/formats_xlsx.csv`).
Те же книги собраны в .docx двумя способами: шапка таблиц помечена
«повторять как заголовок» и не помечена (по умолчанию в Word).
Генератор — `sandbox/formats/make_xlsx_corpus.py`.

### Извлечение (150 непустых ячеек данных)

| Показатель | .xlsx | .docx, шапка помечена | .docx, шапка не помечена |
|---|---|---|---|
| значение есть в тексте | 100 % | 100 % | 100 % |
| значение в одной строке с подписью строки | 100 % | 98 % | 98 % |
| «ключ: значение» в этой строке | **100 %** | 91 % | **0 %** |
| строка внутри группы: группа в крошках или в строке | **100 %** | 0 % | 0 % |
| формул без сохранённого результата | 1 | — | — |

У .docx с объединённой шапкой ключ теряет нижнюю строку («Суточные:
1200 ₽; 1000 ₽» — что «до 10 дней», а что «свыше», не видно), строка-группа
становится строкой таблицы («Направление: Россия»), объединённая по
вертикали ячейка остаётся только в первой строке. Формула без результата —
особенность файлов, собранных программой (openpyxl); Excel результат
сохраняет. Скрипт — `sandbox/formats/format_stats.py`.

\* Судья поставил 2 общему ответу на x09 («где сделать пропуск»: ответ
без Павла Гурова) — ошибка судьи, как на g33. Без неё .docx без пометки —
16 / 2 / 6, балл 1,42.

**Вывод: .xlsx не хуже .docx** — разница в пределах шума, направление в
пользу .xlsx (x08 «справка 2-НДФЛ» и x12 «авансовый отчёт» .docx потерял:
строки без ключей, расстояние 0,585–0,590, модель отказалась по выдержкам).

**Общие провалы — у всех трёх вариантов** (x09 пропуск, x11 увольнение,
x19 ДМС, x21 мобильная связь): нужная строка далеко от вопроса, расстояние
0,593–0,687 — выше порога 0,59, вопрос получает общий ответ. Это поиск по
таблицам вообще, а не формат. Проба без ответов
(`sandbox/formats/row_chunks_probe.py`): если каждую строку таблицы
эмбеддить отдельным фрагментом с теми же крошками, строка ближе текущего
фрагмента в 19 из 24 вопросов, порог проходит 21 вопрос вместо 20 (x21:
0,602 → 0,445; x19: 0,687 → 0,606; x09 и x11 — без изменений, ~0,60:
«где сделать пропуск» против «Вопросы: Пропуска, парковка…»). Это
изменение нарезки для всех форматов — отдельная задача (ML-4б), с проверкой
на золотом dev; в .xlsx не входит.

**Остальное не портится.** Золотой dev, 33 вопроса, поиск с пятью книгами в
корпусе и без: MRR 0,730 → 0,730, Hit@5 0,750 → 0,750. Два вопроса вне
документов находят строку из книг ближе всего (0,62 и 0,69) — выше порога,
ответ прежний.

Стоимость: ≈ 35 ₽ (75 ответов Flash, 75 вердиктов судьи, эмбеддинги).

## Находка: таблицы .docx без помеченной шапки теряют ключи (01.10)

Нашлась при сравнении с .xlsx, касается продукта уже сейчас. mammoth
делает `<th>` только из строк, помеченных в Word «повторять как
заголовок» (по умолчанию выключено). Если `<th>` нет, markdownify 1.2
ставит над таблицей пустую шапку `|  |  |`, и `preprocess` линеаризует
строки без ключей: «Европа; 3500 ₽; 3000 ₽» вместо «Направление: Европа;
Суточные: 3500 ₽». На наборе выше — 0 % ключей против 91 %.

В демо-корпусе не проявилось: в .docx «Победители Старт-ИИ-1» шапка
помечена, остальные документы — PDF. У клиентов документы Word с
таблицами — обычное дело.

Что делать (следующий PR ML, отдельно от .xlsx):
1. **`preprocess`** (зона ML): пустая шапка GFM → первая строка таблицы
   становится шапкой, если похожа на шапку (в основном текст, не числа —
   то же правило, что `_is_header` в `xlsx.py`). Замер — этот же набор в
   .docx без пометки + золотой dev.
2. **Объединённые ячейки .docx** (`rowspan`, `colspan`) markdownify не
   разворачивает. Лечится на уровне HTML до markdownify: развернуть
   таблицу в полную сетку. Это извлечение (`extract.py`, бэкенд); ML может
   дать чистую функцию HTML → HTML и пункт BH — после замера п. 1.
