# Подключения к системам компании: что есть и как подключить

Каталог видов подключений (коннекторов), что делает администратор
компании, что — сотрудник, как зеркалируются права и что ещё не
проверено на живых системах. Почему выбраны именно эти системы —
`CONNECTORS-POOL.md` (исследование 09.10) и `CONNECTORS-RESEARCH.md`
(25.09). Приложения Яндекс ID и Битрикс24 — `OAUTH-SETUP.md`.

## Как устроено

- **Общий пул.** Виды ниже — базовые (`KindSpec.base`), кроме
  помеченных «только „Корпоративный“»: на «Базовом» администратор
  выбирает до 5 разных систем, на «Расширенном» — без ограничения;
  системы вне пула — «Корпоративный» (решение 09.10).
- **Два режима прав.**
  - *Организация* (`organization`): одна служебная учётка читает всё, а
    права каждого документа берутся из системы (пользователи, группы,
    «вся компания») и сопоставляются по почте.
  - *Каждый сотрудник сам* (`per_user`): сотрудник подключает свою
    учётку — входом (OAuth) или вводом токена или пароля приложения в
    «Настройки → Мои подключения»; ассистент видит ровно то, что этот
    сотрудник видит в системе. Данные сотрудника проверяются в системе
    при сохранении: неверные — сразу ошибка, ничего не сохраняется.
- **Не проверено на живой системе — не в каталоге.** Вид или модуль с
  флагом `preview` компании не видят, пока он не перечислен в
  `CONNECTOR_PREVIEW_KINDS` / `CONNECTOR_PREVIEW_MODULES`; `cli
  connector-check` видит его и без флага — для той самой проверки.
- **Адреса** — только `https` и публичные (проверка адресов в коде и
  правила ядра, `DEPLOY.md` §9a). Система во внутренней сети клиента без
  публичного адреса не подключится (`OPEN-QUESTIONS.md`, П-11).

## По видам

### Битрикс24 (облако и коробка)

Тот же вид для облака и коробки. Коробке нужны публичный HTTPS-адрес с
действующим сертификатом, исходящий https к `oauth.bitrix24.tech` и
входящий https от kronto; локальное приложение с правами `disk`,
`landing` (для «Базы знаний 2.0» — `note`) и нашим адресом возврата —
`OAUTH-SETUP.md`. Коробка со «своим провайдером авторизации» не
поддерживается: адреса выдачи токенов у неё нет в документации.

### Яндекс 360: Диск, общие диски, Вики

Сотрудник подключает свой аккаунт в «Мои подключения»; kronto обходит
его Диск (`disk:/`) и, при указанном ID организации, общие диски
организации (`virtual-disks`) и Вики. Папка, которую коллега открыл
сотруднику по персональному доступу, в вебе лежит в разделе «Общий
доступ → Папки», а не в «Файлах». В документации REST API Диска метода
для таких папок нет (есть только административный
`public/resources/admin/accessible-resources` — токеном администратора
организации), поэтому они в kronto не попадают, пока не проверены на
живой организации (`RISKS.md`, №38). Обходной путь: положить документы
на общий диск организации или скопировать документы на свой Диск.

### Яндекс Трекер (модуль Яндекс 360)

Задача — документ (заголовок, статус, описание, комментарии), вложения
поддерживаемых форматов — отдельные файлы. Право `tracker:read` в
приложении Яндекс ID: если добавить его к уже работающему приложению,
Яндекс отзовёт выданные токены и сотрудникам придётся подключиться
заново; без этого — отдельное приложение и отдельное подключение только
с Трекером. Нужен ID организации Яндекс 360 (или, если Трекер подключён
к организации Yandex Cloud, её ID в отдельном поле); очереди можно
ограничить списком.

### Google Диск (только Google Workspace)

Личные Gmail не поддерживаются: для них Google требует платную проверку
приложения. Администратор компании в своём Google Cloud включает Google
Drive API и Admin SDK API, создаёт сервисный аккаунт и JSON-ключ, в
консоли Workspace (Безопасность → Доступ к данным → Управление API →
Делегирование на уровне домена) вписывает client_id ключа и ровно три
scope: `https://www.googleapis.com/auth/drive.readonly`,
`https://www.googleapis.com/auth/admin.directory.user.readonly`,
`https://www.googleapis.com/auth/admin.directory.group.member.readonly`.
В форме kronto — домены компании, почта администратора Workspace и
JSON-ключ. Модули: «Общие диски» (от имени их участников) и «Диски
сотрудников» (каждый «Мой диск», дороже по квоте). Права — по
разрешениям Drive: пользователи, группы с вложенными, «все в домене» и
«все по ссылке» — вся компания. Документы, Таблицы, Презентации
экспортируются в docx, xlsx, pptx (лимит экспорта Google — 10 МБ).

### WebDAV-семейство: Nextcloud, ownCloud, Seafile, VK WorkSpace, Облако Mail.ru, NAS

Администратор вводит адрес сервера и, по желанию, папки от корня
сотрудника; сотрудник — логин и пароль приложения (Nextcloud и
ownCloud — «Настройки → Безопасность»; VK WorkSpace и Mail.ru — пароль
для внешнего приложения; Seafile при SSO — пароль WebDAV; NAS — пароль
учётки с включённым WebDAV). Для Nextcloud есть и вход OAuth2: клиент в
«Администрирование → Безопасность → Клиенты OAuth 2.0» с нашим адресом
возврата. Ассистент видит то же, что сотрудник: свои файлы, общие и
групповые папки. Общий файл Nextcloud и ownCloud — один документ на
всех, у остальных систем — копия на каждого сотрудника (сквозного id
файла у них нет). Больше 20 000 элементов или глубже 32 уровней —
ошибка, нужно сузить «Папки». Облачный адрес WebDAV VK WorkSpace не
задокументирован — вводит администратор.

### Kaiten

Администратор — адрес пространства (облако или своя установка) и, по
желанию, ID пространств для вложений; каждый сотрудник — свой API-токен
из профиля Kaiten (`/profile/api-key`). Модули «Документы» (из
ProseMirror в Markdown) и «Вложения карточек». Права — только у
сотрудника: метода «кто приглашён в документ» в API Kaiten нет.

### Outline и Yonote

API-ключ от учётной записи **администратора** (Настройки → API) и, для
своей установки, адрес. Коллекция, открытая всей рабочей области, видна
всей компании; закрытая — её участникам и участникам её групп (в
Outline — и участникам самого документа). Владелец ключа должен
**состоять в закрытых коллекциях**: иначе Outline не отдаёт их документы
даже администратору. Черновики и шаблоны не берутся.

### BookStack

API-токен (Token ID и Token Secret; профиль → «API-токены») от учётной
записи **администратора** — у роли должно быть право «Access System
API» — и адрес своей установки. Модули «Книги, главы и страницы» (HTML
страниц с подставленными включениями) и «Вложения страниц» (файлы,
ссылки не берутся). Права — как их считает сам BookStack: роль Admin
видит всё; иначе решают записи роли и «Все остальные» на странице, затем
в главе, затем в книге, а без них — системные права роли («просмотр
всего» или только своих страниц); явный запрет одной роли перевешивает
право «по умолчанию» другой. «Вся компания» — только если право даёт
роль, в которой состоят все пользователи, и страницу видит каждый; иначе
— почты тех, кто видит. Гость (роль Public) не учитывается; черновики и
шаблоны не берутся. Лимит API BookStack — 180 запросов в минуту: большая
вики обновляется медленно. Живая проверка (15.10, v26.09.1): права
адаптера совпали с тем, что BookStack отдаёт каждому из пяти
пользователей его собственным токеном.

### Wiki.js 2.x

Администратор Wiki.js включает API («Администрирование → API») и
создаёт ключ с полным доступом (Full Access); в форме kronto — адрес
своей Wiki.js и этот ключ. Ключ группы не принимается: без
`manage:system` Wiki.js не отдаёт группы и почты. Страницы всех локалей;
права — как их считает сам Wiki.js при показе страницы: страница,
открытая гостям, видна всей компании, остальные — активным
пользователям, которым её открывают правила их групп (более длинный
путь побеждает, при равном — точный тип правила, затем запрет; локали и
теги учитываются). REGEX-правило, которое нельзя посчитать так же, как
JavaScript, — в сторону закрытости. В новой установке у группы Guests
правило на всю вики — пока его не сузят, все страницы станут «всей
компанией». Неопубликованные страницы и страницы вне окна публикации не
берутся. Очень большая вики (список страниц больше 20 МБ) не обходится:
в Wiki.js 2 нет постраничного списка страниц.

### Microsoft 365: SharePoint и OneDrive (только «Корпоративный»)

Администратор компании в Entra ID регистрирует приложение, выдаёт ему
application permissions Microsoft Graph `Sites.Read.All`,
`Files.Read.All`, `User.Read.All`, `GroupMember.Read.All` с согласием
администратора и создаёт секрет клиента; в форме kronto — ID клиента
(tenant), ID приложения и секрет. Модули «SharePoint» (сайты с
подсайтами, библиотеки документов) и «OneDrive сотрудников». Права — по
разрешениям каждого файла: пользователи, группы Entra с вложенными,
владельцы и участники сайта группы Microsoft 365; группы SharePoint вне
этого (посетители, свои) и люди, добавленные в них напрямую, прав не
получают. Ссылка общего доступа — даже «всем в организации» или
анонимная — не делает документ видимым всем: его видят только
перечисленные в ней. «Все, кроме внешних пользователей» пока не
переносится (никому) — до живой проверки. Можно ограничиться списком
сайтов (`Sites.Selected`, без OneDrive). Подписку из России не оформить
— написано и проверено только по документации Microsoft.

### amoCRM / Kommo

Администратор amoCRM создаёт в аккаунте интеграцию (Настройки →
Интеграции → Создать) с доступами «Доступ к данным аккаунта» и «Доступ к
файлам»; Redirect URI — адрес возврата kronto. В форме kronto — адрес
аккаунта (`https://компания.amocrm.ru` или `https://компания.kommo.com`)
и ID интеграции; секретный ключ — в учётные данные подключения. Каждый
сотрудник авторизует интеграцию своим входом и видит ровно то же, что в
amoCRM: файлы сделок, контактов и компаний, открытых ему. По
документации amoCRM авторизовать интеграцию может только администратор
аккаунта — остальные сотрудники, вероятно, подключиться не смогут
(проверить живьём). Поле «Воронки» сужает сделки; на каждую сделку —
отдельный запрос при лимите 7 запросов в секунду на интеграцию, поэтому
больше 5000 сущностей в модуле — ошибка `too_many_entities` с подсказкой
сузить «Воронки». Примечания не берутся.

### ELMA365, раздел «Файлы» (только «Корпоративный»)

Администратор kronto вводит адрес компании (облако —
`https://<компания>.elma365.ru`, коробка — свой домен) и, по желанию, ID
папок раздела «Файлы». Токены выпускает только администратор ELMA365
(«Администрирование → Токены»): на каждого сотрудника свой, от его
имени; сотрудник вставляет свой токен в «Мои подключения». Прав файла со
списком пользователей в API ELMA365 нет, поэтому ассистент берёт только
папки и файлы, которые прошли поштучную проверку токеном сотрудника
(403 — пропуск): это запрос на каждую папку и файл на каждого сотрудника
при лимите облака 90 + 5 × лицензий запросов в минуту, большой раздел
загружается за несколько запусков. Вложения элементов приложений не
берутся. Если администратор раздаст всем токен одного пользователя,
kronto этого не распознает.

### MediaWiki (своя вики)

Администратор вводит адрес api.php (`https://wiki.company.ru/w/api.php`),
бот-пароль служебной учётки (Служебная:BotPasswords, права «Основные» —
`basic`; имя вида `Логин@бот`, основной пароль не принимается) и
сопоставление «логин в вики = почта» для сотрудников: почт пользователей
API MediaWiki не отдаёт. Прав на отдельные страницы в MediaWiki нет —
документ видят сотрудники из сопоставления, у кого в вики есть право
чтения и нет блокировки (проверяется при каждом запуске); «вся компания»
не ставится даже для вики, открытой без входа. По умолчанию берётся
основное пространство имён; другие — списком. Если стоит Lockdown или
похожее расширение, закрывающее пространства по группам, без списка
ничего не синхронизируется: администратор перечисляет только
пространства, открытые всем читателям (для файлов — и «Файл»). Модули
«Страницы» (HTML после разбора, с шаблонами) и «Файлы»; файлы за
img_auth.php не берутся — сессия бот-пароля там не действует.

### DokuWiki

Своя установка 2024-02 «Kaos» и новее: только JSON-RPC. Администратор
DokuWiki включает `remote` и вписывает служебную учётку в `remoteuser`;
учётка должна быть суперпользователем — проверять чужие права DokuWiki
разрешает только ему. В форме kronto — адрес вики, токен учётки или её
логин и пароль (без «:»), и список сотрудников «логин почта» (по строке
или через «;»): пользователей с почтами API DokuWiki не отдаёт. Права
считает сама DokuWiki (`core.aclCheck` для каждого логина из списка);
«вся компания» не ставится даже для `@ALL`, сотрудник не из списка не
видит ничего. Модули «Страницы» (HTML) и «Медиафайлы»; обход сужает поле
«Пространства». Личные пространства с правилами `%USER%` сотрудникам не
достаются; удалённого из DokuWiki пользователя нужно убрать из списка.

### Jira Software Server / Data Center

Адрес Jira и персональный токен доступа **администратора Jira** (или
администратора нужных проектов): кто может открыть задачу, Jira отвечает
только им. По желанию — ключи проектов и фильтр JQL (например,
`updated >= -365d`; без ORDER BY). Модули «Задачи» (описание и
комментарии, ключ и заголовок — в названии) и «Вложения задач». Права
каждой задачи — ответ самой Jira с учётом схемы прав проекта (группы,
роли, «любой», автор, исполнитель) и уровня безопасности; «любой» — все
активные пользователи, а не вся компания. Комментарии с ограничением
видимости не берутся. Проект, где токен не администратор, не
индексируется; не администратор нигде — подключение останавливается с
`admin_required`. Права перечитываются каждым запуском — в проектах с
«Автором задачи» и для задач с уровнем безопасности это запрос на
задачу. Контейнеру стенда нужно 4 ГБ памяти.

### Р7-Офис Корпоративный сервер 2019 (только «Корпоративный»)

Для сервера 2019 (на основе ONLYOFFICE Workspace); у сервера 2024 другое
API, он не подходит. Адрес портала, логин и пароль администратора
портала или модуля «Документы» без двухфакторной проверки, по желанию —
ID папок внутри «Общих документов». Берутся только «Общие документы».
Права — по настройкам доступа файла и его папок: сотрудники, группы,
«Все» (явный список активных сотрудников), администраторы портала читают
всё; доступ по ссылке ничего не открывает. Если у файла свои настройки
доступа внутри закрытой папки, он может дойти не до всех, кто видит его
в Р7: API не отличает свою запись файла от унаследованной, правило
решает в сторону закрытости. Написано по документации Р7, живой
проверки не было.

### Сетевые папки (SMB) через агента

Файловый сервер из интернета не виден, поэтому документы и права NTFS
присылает агент kronto, установленный в сети компании (`agent/`,
протокол — `SMB-AGENT.md`). Документ виден только сотрудникам, чьи почты
агент вычислил из прав папки (группы домена раскрываются через LDAP).
Только «Корпоративный». Ключ агента администратор выпускает в карточке
подключения («Выпустить ключ агента»; виден один раз, прежний
перестаёт действовать) или командой `cli agent-token --code <компания>
--connector <id>`.

### Публичный сайт или справочный центр

Адрес сайта или раздела (`https://company.ru/help/`): обходятся только
страницы под ним, открытые без входа; ключей нет, документы видит вся
компания. Сначала robots.txt (агент `kronto-bot`, Crawl-delay
соблюдается), затем sitemap.xml, без неё — ссылки до заданной глубины.
Файлы pdf, docx, xlsx, pptx, doc, txt, md по ссылкам на том же сайте
подхватываются. Сайты, где текст строит JavaScript, не читаются.
Большому сайту нужна карта с lastmod; обновление — раз в сутки.

## Живая проверка (после неё вид открывается)

Системы, которые ставятся у себя, проверены на стендах в Docker
(`tests/live/{webdav,nextcloud,owncloud,seafile,outline,bookstack,wikijs,mediawiki,dokuwiki,jira_dc,smb}/README.md`):
стенд по HTTPS на 127.0.0.1 с выдуманной компанией, тесты пропускаются
без переменных окружения. Что учтено по итогам: Apache mod_dav (и NAS на
нём) отвечает 401 на закрытую папку — она пропускается, а не гасит
подключение; Outline 1.10 отдаёт группы коллекции в `groupMemberships`;
слишком большое или глубокое дерево папок останавливает запуск с кодом
`tree_too_large` / `tree_too_deep` и подсказкой сузить «Папки». SeafDAV
в Seafile по умолчанию выключен — его включает администратор Seafile.

Общая команда — `python -m corp_ed.cli connector-check --kind <вид>
--config … --credential … [--module …] --fetch 2 --record DIR`; записанные
ответы — без ключей и токенов. Что проверить по каждому виду и какие
доступы нужны — в списке ручных дел владельца (09.10) и в сообщениях
коммитов коннекторов. После проверки вид добавляется в
`CONNECTOR_PREVIEW_KINDS` (или с него снимается `preview` в коде).
