# Подключения к системам компании: что есть и как подключить

Каталог видов подключений (коннекторов), что делает администратор
компании, что — сотрудник, как зеркалируются права и что ещё не
проверено на живых системах. Почему выбраны именно эти системы —
`CONNECTORS-POOL.md` (исследование 09.10) и `CONNECTORS-RESEARCH.md`
(25.09). Приложения Яндекс ID и Битрикс24 — `OAUTH-SETUP.md`.

## Как устроено

- **Общий пул.** Все виды ниже — базовые (`KindSpec.base`): на
  «Базовом» администратор выбирает до 5 разных систем, на «Расширенном»
  — без ограничения; системы вне пула — «Корпоративный» (решение 09.10).
- **Два режима прав.**
  - *Организация* (`organization`): одна служебная учётка читает всё, а
    права каждого документа берутся из системы (пользователи, группы,
    «вся компания») и сопоставляются по почте.
  - *Каждый сотрудник сам* (`per_user`): сотрудник подключает свою
    учётку — входом (OAuth) или вводом токена или пароля приложения в
    «Настройки → Мои подключения»; ассистент видит ровно то, что этот
    сотрудник видит в системе. Данные сотрудника проверяются в системе
    при сохранении: неверные — сразу ошибка, ничего не сохраняется.
- **Не проверено на живой системе — не в каталоге.** Вид или модуль с
  флагом `preview` компании не видят, пока он не перечислен в
  `CONNECTOR_PREVIEW_KINDS` / `CONNECTOR_PREVIEW_MODULES`; `cli
  connector-check` видит его и без флага — для той самой проверки.
- **Адреса** — только `https` и публичные (проверка адресов в коде и
  правила ядра, `DEPLOY.md` §9a). Система во внутренней сети клиента без
  публичного адреса не подключится (`OPEN-QUESTIONS.md`, П-11).

## По видам

### Битрикс24 (облако и коробка)

Тот же вид для облака и коробки. Коробке нужны публичный HTTPS-адрес с
действующим сертификатом, исходящий https к `oauth.bitrix24.tech` и
входящий https от kronto; локальное приложение с правами `disk`,
`landing` (для «Базы знаний 2.0» — `note`) и нашим адресом возврата —
`OAUTH-SETUP.md`. Коробка со «своим провайдером авторизации» не
поддерживается: адреса выдачи токенов у неё нет в документации.

### Яндекс Трекер (модуль Яндекс 360)

Задача — документ (заголовок, статус, описание, комментарии), вложения
поддерживаемых форматов — отдельные файлы. Право `tracker:read` в
приложении Яндекс ID: если добавить его к уже работающему приложению,
Яндекс отзовёт выданные токены и сотрудникам придётся подключиться
заново; без этого — отдельное приложение и отдельное подключение только
с Трекером. Нужен ID организации Яндекс 360 (или, если Трекер подключён
к организации Yandex Cloud, её ID в отдельном поле); очереди можно
ограничить списком.

### Google Диск (только Google Workspace)

Личные Gmail не поддерживаются: для них Google требует платную проверку
приложения. Администратор компании в своём Google Cloud включает Google
Drive API и Admin SDK API, создаёт сервисный аккаунт и JSON-ключ, в
консоли Workspace (Безопасность → Доступ к данным → Управление API →
Делегирование на уровне домена) вписывает client_id ключа и ровно три
scope: `https://www.googleapis.com/auth/drive.readonly`,
`https://www.googleapis.com/auth/admin.directory.user.readonly`,
`https://www.googleapis.com/auth/admin.directory.group.member.readonly`.
В форме kronto — домены компании, почта администратора Workspace и
JSON-ключ. Модули: «Общие диски» (от имени их участников) и «Диски
сотрудников» (каждый «Мой диск», дороже по квоте). Права — по
разрешениям Drive: пользователи, группы с вложенными, «все в домене» и
«все по ссылке» — вся компания. Документы, Таблицы, Презентации
экспортируются в docx, xlsx, pptx (лимит экспорта Google — 10 МБ).

### WebDAV-семейство: Nextcloud, ownCloud, Seafile, VK WorkSpace, Облако Mail.ru, NAS

Администратор вводит адрес сервера и, по желанию, папки от корня
сотрудника; сотрудник — логин и пароль приложения (Nextcloud и
ownCloud — «Настройки → Безопасность»; VK WorkSpace и Mail.ru — пароль
для внешнего приложения; Seafile при SSO — пароль WebDAV; NAS — пароль
учётки с включённым WebDAV). Для Nextcloud есть и вход OAuth2: клиент в
«Администрирование → Безопасность → Клиенты OAuth 2.0» с нашим адресом
возврата. Ассистент видит то же, что сотрудник: свои файлы, общие и
групповые папки. Общий файл Nextcloud и ownCloud — один документ на
всех, у остальных систем — копия на каждого сотрудника (сквозного id
файла у них нет). Больше 20 000 элементов или глубже 32 уровней —
ошибка, нужно сузить «Папки». Облачный адрес WebDAV VK WorkSpace не
задокументирован — вводит администратор.

### Kaiten

Администратор — адрес пространства (облако или своя установка) и, по
желанию, ID пространств для вложений; каждый сотрудник — свой API-токен
из профиля Kaiten (`/profile/api-key`). Модули «Документы» (из
ProseMirror в Markdown) и «Вложения карточек». Права — только у
сотрудника: метода «кто приглашён в документ» в API Kaiten нет.

### Outline и Yonote

API-ключ от учётной записи **администратора** (Настройки → API) и, для
своей установки, адрес. Коллекция, открытая всей рабочей области, видна
всей компании; закрытая — её участникам и участникам её групп (в
Outline — и участникам самого документа). Владелец ключа должен
**состоять в закрытых коллекциях**: иначе Outline не отдаёт их документы
даже администратору. Черновики и шаблоны не берутся.

### Публичный сайт или справочный центр

Адрес сайта или раздела (`https://company.ru/help/`): обходятся только
страницы под ним, открытые без входа; ключей нет, документы видит вся
компания. Сначала robots.txt (агент `kronto-bot`, Crawl-delay
соблюдается), затем sitemap.xml, без неё — ссылки до заданной глубины.
Файлы pdf, docx, xlsx, pptx, doc, txt, md по ссылкам на том же сайте
подхватываются. Сайты, где текст строит JavaScript, не читаются.
Большому сайту нужна карта с lastmod; обновление — раз в сутки.

## Живая проверка (после неё вид открывается)

Общая команда — `python -m corp_ed.cli connector-check --kind <вид>
--config … --credential … [--module …] --fetch 2 --record DIR`; записанные
ответы — без ключей и токенов. Что проверить по каждому виду и какие
доступы нужны — в списке ручных дел владельца (09.10) и в сообщениях
коммитов коннекторов. После проверки вид добавляется в
`CONNECTOR_PREVIEW_KINDS` (или с него снимается `preview` в коде).
