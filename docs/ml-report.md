## Поиск (A7): E1–E3 и M1, векторы Яндекса

MRR (Hit@5); в скобках — Hit@5. Значимость — `eval.compare`:
95% CI разницы по бутстрепу плюс парный перестановочный тест.

| Конфигурация | Серебряный dev (118) | Серебряный test (57) | Демо-вопросы (23) |
|---|---|---|---|
| v1 1000/100, вектор | 0.392 (0.63) | 0.456 (0.65) | 0.231 (0.39) |
| **v2 400/50, вектор** (текущая) | 0.386 (0.56) | 0.501 (0.67) | 0.617 (0.70) |
| v2 400/50 без крошек | **0.506** (0.69) | 0.575 (0.74) | 0.342 (0.57) |
| v2 400/50, крошки без названия | 0.443 (0.63) | 0.540 (0.70) | 0.403 (0.52) |
| v2 600/0 | 0.454 (0.65) | — | 0.691 (0.91) |
| v2 600/50 | 0.429 (0.65) | — | **0.717 (0.96)** |
| v2 800/0 | 0.463 (0.63) | — | 0.586 (0.83) |
| v2 400/50, BM25 | 0.639 (0.81) | 0.681 (0.77) | 0.469 (0.70) |
| **v2 400/50, гибрид 1.0/0.5** | 0.536 (**0.77**) | — | 0.561 (**0.91**) |
| v2 400/50, гибрид 1.0/1.0 | 0.576 (0.78) | 0.626 (0.77) | 0.576 (0.78) |
| v2 600/0, гибрид 1.0/0.5 | 0.577 (0.78) | — | 0.662 (0.91) |

Выводы:
- **E1 (v1 → v2):** на демо-вопросах +0.386 MRR (p = 0.0008). На
  серебряном — ничья с крошками, +0.114 без них (p = 0.001). v2 остаётся.
- **E2 (крошки): наборы противоречат друг другу, и значимо.**
  - На серебряном без крошек лучше: +0.120 MRR (p = 0.0002), на test то же.
  - На демо-вопросах с крошками лучше: +0.275 MRR (p = 0.0001).

  Объяснение: крошки помогают, когда вопрос сформулирован на уровне темы
  раздела («размер гранта» ↔ заголовок «3. Размер гранта»), и мешают,
  когда вопрос о детали внутри текста. Серебряные вопросы генерируются из
  деталей. Проверил и другое объяснение: «вопрос называет документ» — не
  подтвердилось, без крошек лучше и на таких вопросах. Живые вопросы
  сотрудников ближе к темам. **Решение — на золотом наборе**, до него
  крошки остаются (ТЗ).
- **E3 (размер):** 600 лучше 400/50 на обоих наборах:
  - серебряный: +0.067 MRR (p = 0.016);
  - демо: 600/50 даёт +0.101 MRR (p = 0.011) и +0.26 Hit@5 (p = 0.028).

  250 и 800 не лучше. В реальных токенах 600 ≈ 390, то есть это и есть
  «400 токенов» из ТЗ, посчитанные при 3 символах на токен.
- **M1 (гибрид):** Hit@5 растёт на обоих наборах: на серебряном
  +0.21 (p = 0.0001), на демо +0.22 (p = 0.12, мало вопросов). Стартовые
  веса ТЗ 1.0/0.5 не хуже прочих. BM25 на серебряном сильнее вектора, но
  это перекос синтетики (вопросы лексически близки к чанку): на демо-вопросах
  BM25 не лучше вектора. Подбирать веса на серебряном не стал — это сдвинуло
  бы их к BM25.

## Известные ограничения

- **Сканы PDF не читаются** — только текстовые PDF (OCR вне MVP).
- **Скриншоты не описываются.** В инструкциях половина смысла бывает на
  картинке (у Битрикс24 это решено визуальной моделью — не MVP).
- **Уровни заголовков PDF — по размеру шрифта**, они бывают
  непоследовательны; хлебные крошки у таких документов шумнее.
- **Название документа — в крошках.** Если это имя файла
  («Pravila-otbora_Akselerator-…»), оно шумит в эмбеддинге. Название
  должно быть человеческим.
- **Ссылки удаляются** (ТЗ, A2). На вопрос «где портал?» ответ без URL.
- **Длина в токенах — приближение** `len / 3` с запасом (ТЗ). Реально
  ~4.6 символа на токен: «400 токенов» чанка ≈ 245 реальных, бюджет
  3000 ≈ 1900 реальных. Недооценки на 232 текстах не было.
- **Таблица, продолжающаяся на новой странице**, получает шапку предыдущей
  таблицы, только если совпадает число столбцов.
- **Нет прав доступа внутри компании:** любой сотрудник тенанта видит
  выдержки из любого документа тенанта (не MVP).
- **Без контекста диалога:** каждый вопрос — отдельный.
- **Порог отказа** — единственный механизм отказа до классификатора
  маршрута (не MVP).
- **Синтетический набор перекошен** к вопросам о деталях: решения о
  крошках и весах гибрида по нему не принимаются.
