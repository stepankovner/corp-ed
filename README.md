# corp-ed · Kronto

Ассистент по внутренним документам компании. Администратор загружает
регламенты, положения и инструкции или подключает системы, где они уже
лежат (Битрикс24, Confluence, Яндекс 360). Сотрудник задаёт вопрос
обычными словами и получает ответ со ссылками на фрагменты документов.
Если ответа в документах нет, ассистент честно говорит об этом, а
администратор видит, каких документов не хватает.

Одна установка обслуживает много компаний; данные изолированы тремя
независимыми кольцами, последнее — Row-Level Security в PostgreSQL.

- **Этап, план ML и бэкенда, что согласовать** — [`docs/ROADMAP.md`](docs/ROADMAP.md).
- **Что уже работает и что нет** — [`docs/STATUS.md`](docs/STATUS.md).
- **Открытые вопросы** — [`docs/OPEN-QUESTIONS.md`](docs/OPEN-QUESTIONS.md).

## Что умеет

**Сотрудник**
- задаёт вопрос и получает ответ со ссылками `[1]`, `[2]` на выдержки;
  по ссылке открывается фрагмент документа или сам документ в системе
  компании;
- ставит оценку ответу 👍 / 👎;
- подключает свои аккаунты Битрикс24 и Яндекс 360 («Мои источники») —
  тогда ассистент видит документы, доступные ему лично.

**Администратор компании**
- загружает документы файлами (docx, pdf, txt, md) и подключает системы
  компании: Битрикс24, Confluence Server/DC, Яндекс 360 (Диск и Вики);
- заводит сотрудников или рассылает ссылку-приглашение;
- смотрит отчёт о пробелах — какие вопросы сотрудников документами не
  закрыты, сгруппированные по темам;
- ведёт глоссарий сокращений, видит расход лимита вопросов и журнал
  действий.

**Команда Kronto** (из командной строки)
- заводит компании, места и режим ответа, когда в документах ответа нет:
  общий ответ с пометкой «В документах компании ответа нет» (по
  умолчанию — решение 29.09, в коде переключается в BH-29) или строгий
  отказ.

## Как получается ответ

```
вопрос → эмбеддинг (text-embeddings-v2, 768)
       → поиск ближайших фрагментов в pgvector, только своей компании
       → порог 0,51: дальше — «в документах ответа нет»
       → 5 лучших фрагментов, до 3 000 токенов
       → промпт faq-v2.5 → Alice AI LLM Flash, температура 0
       → ответ со ссылками на фрагменты
```

Документы режутся на фрагменты по 400 токенов с перекрытием 50, по
разделам; в каждый фрагмент добавляется «хлебная крошка» — название
документа и путь разделов. Все эти значения выбраны замерами ML на
проверенном людьми наборе вопросов; как и почему —
[`docs/ml-summary.md`](docs/ml-summary.md).

## Качество ответов

Замеры ML на публичных документах (положения конкурсов Фонда содействия
инновациям, правила акселераторов). Эталонный набор — 52 вопроса,
проверенных людьми: 33 для настройки, 19 закрыты до финальной проверки.

| Что | Результат | На скольких вопросах |
|---|---|---|
| нужный фрагмент среди 5 найденных | 73 % | 26 по документам |
| ответ верный полностью / частично | 16 / 4 | 26 по документам |
| честный отказ, когда ответа в документах нет | 5 из 5 | 5 вне документов |
| скорость против Алисы AI для бизнеса | медиана 0,8 с против 6,2 с | 58 одинаковых вопросов |
| правильность против Алисы AI для бизнеса | 34 против 36 верных — разница в пределах шума | 45 по документам |

Слабое место — вопросы с ложной посылкой и сравнения двух программ:
поиск не всегда находит нужный фрагмент. Подробно:
[`docs/ml-report.md`](docs/ml-report.md), сравнение с Алисой —
[`docs/ml-vs-alice.md`](docs/ml-vs-alice.md). Финальная проверка на
закрытых вопросах — 11–12.10.

## Стек

**Бэкенд:** Python 3.12 · FastAPI · SQLAlchemy 2 (async) + asyncpg ·
PostgreSQL 16 + pgvector · Redis · Alembic · uv · ruff · mypy strict ·
pytest.
**Фронтенд:** React 19 · TypeScript · Vite · TanStack Query · Vitest ·
Playwright.
**Модели:** Yandex Cloud — Alice AI LLM Flash (ответы) и
text-embeddings-v2 (поиск), через OpenAI-совместимый API.

## Запуск

### Docker Compose (разработка)

```bash
cp .env.example .env      # заполнить: пароли, YC_FOLDER_ID, YC_API_KEY
docker compose up --build
```

Поднимаются PostgreSQL с pgvector, Redis, миграции, API с
автоперезагрузкой, воркер и собранный фронтенд. API —
http://localhost:8000, документация API — http://localhost:8000/docs
(вне `production`), интерфейс — http://localhost:8080.

Боевой режим (без `--reload`, без открытых портов базы, приложение под
ролью без прав на DDL): `docker compose -f compose.yaml up -d` — см.
[`docs/DEPLOY.md`](docs/DEPLOY.md).

### Локально (uv)

Нужны PostgreSQL 16 с расширением `vector` и, по желанию, Redis.

```bash
uv sync
uv run alembic upgrade head
uv run uvicorn corp_ed.main:app --reload
uv run python -m corp_ed.worker           # в отдельном терминале
```

### Без ключей Yandex Cloud

Для разработки интерфейса модель не нужна: `LLM_PROVIDER=fake` отвечает
первой найденной выдержкой, эмбеддинги — «мешок слов». С ним поставьте
`RAG_FAQ_MAX_DISTANCE=0.8`, иначе почти всё уйдёт в отказ. Запуск
фронтенда — [`frontend/README.md`](frontend/README.md).

### Первая компания

Компании заводит команда из командной строки — HTTP-ручки для этого нет:

```bash
uv run python -m corp_ed.cli create-tenant \
    --code acme --name "ACME" --seats 50 --admin-email admin@acme.ru
```

Временный пароль администратора CLI спросит скрытым вводом (или возьмёт
первой строкой stdin с `--admin-password-stdin`) и не печатает; при
первом входе его нужно сменить. Общий ответ с пометкой вместо отказа
включается `--not-found-mode general` или командой `set-not-found-mode`.
Остальные команды — `uv run python -m corp_ed.cli --help`.

## Проверки

```bash
uv run ruff check --fix && uv run ruff format
uv run mypy
TEST_DATABASE_URL=postgresql+asyncpg://corp_ed:…@localhost:5432/corp_ed_test \
TEST_REDIS_URL=redis://localhost:6379/15 \
uv run pytest -q --cov
uv run pre-commit install   # один раз
```

Тесты пересоздают схему тестовой базы и работают под ролью без
`SUPERUSER`/`BYPASSRLS`. Без `TEST_REDIS_URL` тесты Redis-реализаций
пропускаются. Проверки фронтенда — в
[`frontend/README.md`](frontend/README.md). Замеры качества ответов —
[`eval/README.md`](eval/README.md).

**CI** — линтер (с правилами bandit), типы, тесты с порогом покрытия
85 %, миграции на пустой базе под владельцем без суперпользователя,
сборка и запуск образа не под root, проверки и сквозные тесты
фронтенда. **Security** (по push и еженедельно) — pip-audit, npm audit,
gitleaks, CodeQL (Python и TypeScript), Trivy по образам и конфигурации,
SBOM.

## Структура

```
src/corp_ed/
  api/v1/         ручки, схемы, зависимости, лимиты частоты
  services/       бизнес-логика
  repositories/   доступ к данным
  domain/         модели и чистые функции (нарезка, поиск, пробелы — ML)
  core/           конфиг, база и изоляция, безопасность, middleware
  llm/            адаптеры Yandex Cloud, ретраи, квоты
  ingest/         извлечение текста из файлов в песочнице
  connectors/     Битрикс24, Confluence, Яндекс 360
  prompts/        промпты (ML)
  main.py         API · worker.py фоновые задачи · cli.py команды · stand.py проверка стенда
frontend/         интерфейс (React + TypeScript)
migrations/       Alembic
deploy/           роль базы, прокси, скрипты тестового стенда
eval/             замеры качества поиска и ответов (ML)
tests/            1 000+ тестов, в том числе tests/security/
docs/             документация, см. ниже
```
