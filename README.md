# corp-ed · Kronto

Ассистент по внутренним документам компании. Администратор загружает
регламенты, положения и инструкции или подключает системы, где они уже
лежат (Битрикс24, Confluence, Яндекс 360). Сотрудник задаёт вопрос
обычными словами и получает ответ со ссылками на фрагменты документов.
Если ответа в документах нет, ассистент честно говорит об этом, а
администратор видит, каких документов не хватает.

Одна установка обслуживает много компаний; данные изолированы тремя
независимыми кольцами, последнее — Row-Level Security в PostgreSQL.

- **Этап, план ML и бэкенда, что согласовать** — [`docs/ROADMAP.md`](docs/ROADMAP.md).
- **Что уже работает и что нет** — [`docs/STATUS.md`](docs/STATUS.md).
- **Открытые вопросы** — [`docs/OPEN-QUESTIONS.md`](docs/OPEN-QUESTIONS.md).

## Что умеет

**Посетитель сайта** (тот же домен, что приложение)
- главная, тарифы, безопасность, о компании, помощь — готовым HTML;
- песочница: вопрос по документам вымышленной компании без входа;
- запись на созвон; юридические страницы — черновики до текстов юриста.

**Сотрудник**
- учётка одна на все компании: регистрация с подтверждением почты, вход
  без кода компании, переключатель компаний в шапке, вступление по
  ссылке или коду приглашения;
- второй фактор: код на почту с нового устройства, приложение,
  ключ доступа, резервные коды; «запомнить устройство», активные сеансы;
- чат как в Claude и ChatGPT: диалоги на сервере (поиск, закрепление),
  ответ печатается по мере генерации, «Остановить», «Ответить заново»,
  правка вопроса, ссылки `[1]`, `[2]` на выдержки с панелью фрагмента,
  подсказки вопросов, 👍 / 👎 с комментарием;
- вложение к вопросу («спроси по этому договору») — в базу компании не
  попадает; поделиться диалогом по ссылке внутри компании;
- профиль, справочник коллег, уведомления, помощь и «Написать в
  поддержку»; свои аккаунты Битрикс24 и Яндекс 360 — тогда ассистент
  видит документы, доступные ему лично;
- установка на телефон: иконка и полноэкранный режим.

**Администратор компании**
- аналитика без имён: вопросы по дням, доля без ответа, оценки, частые
  темы; настройки компании — название, логотип, режим «ответа нет»,
  правила второго фактора, домены почты;
- люди: приглашения ссылкой и кодом, заявки, роли, удаление из
  компании, места по тарифу; отделы и папки с доступом по отделам;
- «Источники»: файлы (docx, doc, xlsx, pptx, pdf, txt, md) и системы
  компании — Битрикс24, Confluence Server/DC, Яндекс 360 (Диск и Вики);
  права на документы повторяются из систем;
- отчёт о пробелах — какие вопросы документами не закрыты, по темам;
  глоссарий сокращений, журнал действий, тариф и заявка на смену,
  чек-лист первых шагов.

**Команда kronto**
- «Панель kronto»: заявки на подключение компаний, компании (тариф,
  места, срок пилота, приостановка), расход на модели, поиск человека
  для помощи со входом, записи на созвон, обращения в поддержку. Вход —
  только с приложением или ключом доступа; в команду добавляет только
  сервер (`cli staff add`);
- остальное — командами на сервере (`cli --help`): создание компании,
  режим «ответа нет» (общий ответ с пометкой по умолчанию или строгий
  отказ), сброс пароля администратора, переиндексация.

## Как получается ответ

```
вопрос → эмбеддинг (text-embeddings-v2, 768)
       → поиск ближайших фрагментов в pgvector, только своей компании
       → порог 0,59: дальше — «в документах ответа нет»
       → 5 лучших фрагментов, до 3 000 токенов
       → промпт faq-v2.5 → Alice AI LLM Flash, температура 0
       → ответ со ссылками на фрагменты
```

Документы режутся на фрагменты по 400 токенов с перекрытием 50, по
разделам; в каждый фрагмент добавляется «хлебная крошка» — название
документа и путь разделов. Все эти значения выбраны замерами ML на
проверенном людьми наборе вопросов; как и почему —
[`docs/ml-summary.md`](docs/ml-summary.md).

## Качество ответов

Замеры ML на публичных документах (положения конкурсов Фонда содействия
инновациям, правила акселераторов). Эталонный набор — 58 вопросов,
проверенных людьми: 39 для настройки, 19 закрыты до финальной проверки.

| Что | Результат | На скольких вопросах |
|---|---|---|
| нужный фрагмент среди 5 найденных | 79 % (27 из 34) | 34 по документам, 01.10 |
| ответ верный полностью / частично | 19 / 3 | 28 по документам, 29.09 |
| честный отказ, когда ответа в документах нет | 5 из 5 | 5 вне документов |
| скорость против Алисы AI для бизнеса | медиана 0,8 с против 6,2 с | 58 одинаковых вопросов |
| правильность против Алисы AI для бизнеса | 34 против 36 верных — разница в пределах шума | 45 по документам |

Слабое место — вопросы с ложной посылкой и сравнения двух программ:
поиск не всегда находит нужный фрагмент. Подробно:
[`docs/ml-report.md`](docs/ml-report.md), сравнение с Алисой —
[`docs/ml-vs-alice.md`](docs/ml-vs-alice.md). Финальная проверка на
закрытых вопросах — 11–12.10.

Проверка стенда 02.10 на синтетической компании (17 документов всех
форматов, 155 вопросов с известным ответом) — 117 верных; вне документов
15 из 15 без выдумок. Корпус и вопросы —
[`tests/fixtures/stand_quality/`](tests/fixtures/stand_quality/), отчёт —
[`docs/STAGE-TESTING.md`](docs/STAGE-TESTING.md).

## Стек

**Бэкенд:** Python 3.12 · FastAPI · SQLAlchemy 2 (async) + asyncpg ·
PostgreSQL 16 + pgvector · Redis · Alembic · uv · ruff · mypy strict ·
pytest.
**Фронтенд:** React 19 · TypeScript · Vite · TanStack Query · Vitest ·
Playwright.
**Модели:** Yandex Cloud — Alice AI LLM Flash (ответы) и
text-embeddings-v2 (поиск), через OpenAI-совместимый API.

## Запуск

### Docker Compose (разработка)

```bash
cp .env.example .env      # заполнить: пароли, YC_FOLDER_ID, YC_API_KEY
docker compose up --build
```

Поднимаются PostgreSQL с pgvector, Redis, миграции, API с
автоперезагрузкой, воркер и собранный фронтенд. API —
http://localhost:8000, документация API — http://localhost:8000/docs
(вне `production`), интерфейс — http://localhost:8080.

Боевой режим (без `--reload`, без открытых портов базы, приложение под
ролью без прав на DDL): `docker compose -f compose.yaml up -d` — см.
[`docs/DEPLOY.md`](docs/DEPLOY.md).

### Локально (uv)

Нужны PostgreSQL 16 с расширением `vector` и, по желанию, Redis.

```bash
uv sync
uv run alembic upgrade head
uv run uvicorn corp_ed.main:app --reload
uv run python -m corp_ed.worker           # в отдельном терминале
```

### Без ключей Yandex Cloud

Для разработки интерфейса модель не нужна: `LLM_PROVIDER=fake` отвечает
первой найденной выдержкой, эмбеддинги — «мешок слов». С ним поставьте
`RAG_FAQ_MAX_DISTANCE=0.8`, иначе почти всё уйдёт в общий ответ с
пометкой «В документах компании ответа нет». Запуск
фронтенда — [`frontend/README.md`](frontend/README.md).

### Первая компания

Учётку человек заводит сам: регистрация на сайте с подтверждением почты
(в разработке письма — в журнал API, `MAIL_BACKEND=console`). Компании
подключает команда — по заявке из учётки (`cli requests list`,
`requests approve`) или из командной строки; HTTP-ручки создания
компании нет:

```bash
uv run python -m corp_ed.cli create-tenant \
    --code acme --name "ACME" --seats 50 --admin-email admin@acme.ru
```

Есть учётка с этой почтой — она станет администратором. Нет — CLI
спросит временный пароль скрытым вводом (или возьмёт первой строкой
stdin с `--admin-password-stdin`) и не печатает; при первом входе его
нужно сменить. Строгий отказ вместо общего ответа с
пометкой включается `--not-found-mode strict` или командой
`set-not-found-mode`.
Остальные команды — `uv run python -m corp_ed.cli --help`.

## Проверки

```bash
uv run ruff check --fix && uv run ruff format
uv run mypy
TEST_DATABASE_URL=postgresql+asyncpg://corp_ed:…@localhost:5432/corp_ed_test \
TEST_REDIS_URL=redis://localhost:6379/15 \
uv run pytest -q --cov
uv run pre-commit install   # один раз
```

Тесты пересоздают схему тестовой базы и работают под ролью без
`SUPERUSER`/`BYPASSRLS`. Без `TEST_REDIS_URL` тесты Redis-реализаций
пропускаются. Проверки фронтенда — в
[`frontend/README.md`](frontend/README.md). Замеры качества ответов —
[`eval/README.md`](eval/README.md).

**CI** — линтер (с правилами bandit), типы, тесты с порогом покрытия
85 %, миграции на пустой базе под владельцем без суперпользователя,
сборка и запуск образа не под root, проверки и сквозные тесты
фронтенда. **Security** — на PR: pip-audit, npm audit, gitleaks; на
`main` и еженедельно — ещё CodeQL (Python и TypeScript), Trivy по
образам и конфигурации, SBOM. Коммиты только с документацией (`docs/`,
`*.md`) CI не запускают. Исполнитель — машины GitHub или свой runner: переменная
`RUNS_ON`, [`docs/CI-RUNNER.md`](docs/CI-RUNNER.md). Репозиторий открыт с
03.10 до этапа безопасности — CodeQL работает; после закрытия ему нужен
платный GitHub Code Security (решение А, `OPEN-QUESTIONS.md`).

**Стенд** (`stage.krontoai.ru`) выкатывается сам после зелёного CI на
`main`, и сервер сразу проверяет себя: вход со вторым фактором, загрузка
и индексация, ответы настоящей модели, чат, сотрудник по приглашению и
закрытая папка отдела, песочница, Word и PDF — 22 шага; затем бэкап —
свежий дамп поднимается во временной базе ([`docs/STAGE.md`](docs/STAGE.md)).

## Структура

```
src/corp_ed/
  api/v1/         ручки, схемы, зависимости, лимиты частоты
  services/       бизнес-логика
  repositories/   доступ к данным
  domain/         модели и чистые функции (нарезка, поиск, пробелы — ML)
  core/           конфиг, база и изоляция, безопасность, middleware
  llm/            адаптеры Yandex Cloud, ретраи, квоты
  ingest/         извлечение текста из файлов в песочнице
  connectors/     Битрикс24, Confluence, Яндекс 360
  prompts/        промпты (ML)
  main.py         API · worker.py фоновые задачи · cli.py команды · stand.py проверка стенда
frontend/         интерфейс (React + TypeScript)
migrations/       Alembic
deploy/           роль базы, прокси, мониторинг, скрипты стенда (выкатка,
                  проверка, бэкап с проверкой восстановления)
eval/             замеры качества поиска и ответов (ML)
tests/            1 700+ тестов, в том числе tests/security/;
                  корпус проверки стенда — tests/fixtures/stand_quality/
docs/             документация, см. ниже
```
