# Тесты «чёрного ящика»: что доступно тесту

Тесты этого каталога пишутся **по требованиям, а не по коду**: по ТЗ
(`docs/TZ.md`) и схеме API (`frontend/openapi.json`). Автор тестов код
продукта не читает. Тест видит систему так же, как браузер пользователя и
команда kronto с сервера: HTTP API и несколько команд CLI. Этот файл —
всё, что нужно знать о тестовой среде.

## Как устроен тест

```python
from tests.blackbox.conftest import API, Kronto   # API = "/api/v1"


async def test_something(kronto: Kronto) -> None:
    browser = kronto.browser()
    response = await browser.post(f"{API}/auth/login", json={...})
    assert response.status_code == 200
```

- Тесты асинхронные (`async def`, pytest-asyncio в режиме auto),
  единственная фикстура — `kronto`.
- База пустая в начале каждого теста. Компаний, учёток, документов нет,
  пока тест их не заведёт.
- Приложение — целиком, как в бою: настоящие проверки входа, токены,
  cookie, лимиты частоты запросов, разделение данных компаний, разбор
  файлов, индексация.

## Фикстура `kronto`

| Вызов | Что делает | В бою это |
|---|---|---|
| `kronto.browser()` | новый HTTP-клиент (`httpx.AsyncClient`, адрес `http://test`) со своими cookie — отдельный браузер и отдельное «устройство» | браузер человека |
| `await kronto.create_company(code=, name=, admin_email=, admin_password=None, seats=10, tariff="base", not_found_mode="general")` | заводит компанию и её администратора. Учётки с этой почтой нет — она создаётся с временным паролем `admin_password` (почта считается подтверждённой). Учётка есть — становится администратором. Возвращает `{"id", "code", "account_created"}`. `tariff`: `base`, `extended`, `enterprise`; `not_found_mode`: `general` или `strict` | команда kronto после созвона, `cli create-tenant` |
| `await kronto.enable_totp(email)` | включает учётке приложение-аутентификатор, возвращает секрет base32 | `cli set-totp` для служебных учёток; людям — через настройки |
| `kronto.totp(secret)` | код приложения-аутентификатора для секрета (из `enable_totp` или из ответа API при подключении приложения). **Каждый вызов — новый, ещё не использованный код** | приложение на телефоне |
| `kronto.passkey()` | программный ключ доступа: `.register(options)` — ответ на регистрацию ключа, `.sign(options)` — подпись входа; `options` — объект `publicKey`-параметров, который выдал API. Сайт ключа — `test`, origin — `https://test` | отпечаток, Face ID, аппаратный ключ |
| `await kronto.make_staff(email)` | учётка — в команде kronto (панель команды) | `cli staff add` |
| `await kronto.run_background()` | воркер: индексирует загруженные документы и отправляет письма — до пустых очередей | фоновый процесс |
| `await kronto.inbox(email)` | письма, дошедшие до адреса, по порядку: список `Letter(to, subject, text, html)`. Сам вызывает `run_background()` | почтовый ящик человека |
| `await kronto.last_letter(email)` | последнее письмо на адрес (нет писем — тест падает) | |
| `await kronto.setup_demo()` | вымышленная компания песочницы сайта и её документы | выкатка, `cli demo setup` |
| `await kronto.send_digest(company_code=None)` | недельная сводка администраторам — сейчас, не дожидаясь понедельника. Возвращает число компаний, которым сводка разослана (в колокольчик; письмом — тем, у кого оно включено) | `cli digest --force` |
| `kronto.set_credits_per_seat(n)` | кредитов на место в месяц — `n` вместо 420: пул компании = места × `n`. Чтобы дойти до 80 % и 100 % за несколько вопросов | настройка сервера `BILLING_CREDITS_PER_SEAT` |
| `kronto.model.unavailable = True` | поставщик модели лежит: каждый вызов модели — ошибка | сбой Yandex Cloud |
| `kronto.model.calls` | сколько раз вызывали модель | |

## Тестовая среда

- **Модель — детерминированная заглушка.** Если по вопросу нашлись
  выдержки из документов, ответ: `Режим разработки, ответ без модели. По
  документам: <начало самой близкой выдержки> [1]`. Если не нашлись —
  `Режим разработки: общий ответ без модели.` Фактов модель не
  придумывает. Ответ потоком приходит по словам.
- **Поиск по документам — по общим словам.** Вопрос находит документ,
  если в нём есть те же слова в той же форме («парковка» не найдёт
  «парковки»). Вопрос без общих слов с документами — «ответа в документах
  нет».
- **Документ становится доступен для вопросов** только после
  `await kronto.run_background()` (индексация в фоне, как в бою).
- **Письма** уходят не сразу, а воркером: смотреть через `kronto.inbox()`.
  Коды и ссылки в письмах — настоящие.
- **Регистрация открыта** (самостоятельная регистрация включена).
- **Лимиты частоты** работают как в бою и обнуляются в начале каждого
  теста. Все браузеры теста — с одного IP-адреса.
- **Время не перематывается**: истечение кодов, ссылок и сеансов
  проверить нельзя — такие требования не тестировать.
- **Сеть наружу недоступна**: подключения к Битрикс24, Confluence,
  Яндекс 360 не дойдут до систем. Проверять только то, что видно без
  них: каталог, права, проверку ввода, отказы.
- **Запись на созвон** со страницы тарифов в тестовой среде выключена
  настройкой (в бою включается вместе с опубликованной политикой
  обработки данных).
- Песочница сайта отвечает, только если вызван `kronto.setup_demo()`.

## Правила для тестов

1. Только HTTP API (`kronto.browser()`) и вызовы `kronto` из таблицы.
   Ни базы, ни внутренних модулей продукта, ни подмен.
2. Что проверять — из ТЗ; как к этому обратиться — из схемы API.
3. Если ТЗ прямо говорит, как должно быть, — проверять точно. Если ТЗ
   молчит о детали (точный код ошибки, текст) — проверять то, что
   обязано выполняться при любом разумном решении (например, «отказ:
   код 4xx, данных нет»), и отметить комментарием `# допущение: …`.
4. У каждого теста — докстринг со ссылкой на раздел ТЗ
   (`ТЗ §3: …`).
5. Проверять и «счастливый путь», и отказы: чужая компания, чужая роль,
   без входа, неверный код, повтор, пустой и слишком длинный ввод.
