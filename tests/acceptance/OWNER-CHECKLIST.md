# Облачные кабинеты для приёмки: список дел владельца

Для чего: набор приёмки (`README.md` рядом) уже проходит на системах в
Docker. Облачные системы он проверит так же, как только в каждой есть
тестовый кабинет, в нём лежат документы корпуса и права по манифесту, а
сценарий получил учётные данные. Здесь — что зарегистрировать и куда
положить ключи.

Условия сверены **15.10.2026** по страницам вендоров (ссылки у каждой
системы). Сайты меняют условия, поэтому перед оплатой открывайте
страницу заново. Где в источниках ответа не нашёл — так и написано
(«не нашёл»), это не значит «нет». Источники вроде toolfox, startpack и
статей на Хабре — не вендор: помечены «сторонний источник».

## Общее для всех систем

- **Регистрировать на ИП и домен `krontoai.ru`.** Вымышленные — только
  сотрудники (ФИО) и документы; кабинеты, платежи и домен настоящие.
- **Почты сотрудников.** Письма-приглашения должны доходить, поэтому в
  облаке учётные записи заводятся на `<логин>@krontoai.ru`, а не на
  вымышленном `@severny-veter.test`. Нужны шесть адресов — логины из
  `manifest.toml`, раздел `[cloud]`: `vetrov`, `belova`, `petrenko`,
  `lebedeva`, `ershov`, `nikitina`. Проще всего одним заходом: у
  регистратора домена включить пересылку «любой адрес домена → один
  ящик владельца» (или почтовый хостинг домена) и заводить все кабинеты на
  эти шесть адресов. В файле учётных данных для таких систем
  выставляется `extra.email_domain = "krontoai.ru"`, и сценарий создаёт в
  kronto сотрудников с теми же почтами — по ним kronto сопоставляет права.
- **Шесть человек**, по одному из отделов, нужны затем, чтобы у каждой
  закрытой зоны (зарплаты, приказы о премиях, юридические споры) были и
  читатели, и не читатели. Роль первого пользователя — администратор.
- **Документы кладутся по плану**: `python -m tests.acceptance.run
  --plan --system <система>` печатает «зона / подпапка / название /
  формат» и кто должен видеть каждый документ. Файлы в нужном формате —
  `python -m tests.acceptance.corpus.build ПАПКА` (docx, xlsx, pptx, pdf, md,
  txt собираются из исходников; Markdown-страницы вики — исходники из
  `corpus/` как есть). Автоматического засева облаков нет: сценарий
  умеет проверять уже разложенное (первая синхронизация, повторная, права
  каждого из шести), а шаги изменений в облаке пропускает (`skip`,
  причина — в таблице), пока не написан засев для этой системы.
- **Куда класть ключи.** Один JSON-файл вне репозитория,
  `~/.kronto-acc/credentials.json` (права 0600; другой путь — `--credentials`
  или переменная `ACC_CREDENTIALS`). Ключ верхнего уровня — идентификатор
  системы из манифеста. Поля подключения (`config`), учётные данные
  организации (`organization`), секреты приложения (`app`), учётные данные
  каждого сотрудника (`users.<логин>`). Те же поля можно задать
  переменными окружения: `ACC_<СИСТЕМА>_<ПОЛЕ>` и
  `ACC_<СИСТЕМА>_<ЛОГИН>_<ПОЛЕ>` (всё в верхнем регистре), например
  `ACC_KAITEN_BASE_URL`, `ACC_KAITEN_VETROV_TOKEN`.
- Проверка готовности: `python -m tests.acceptance.run --list`.
  Запуск: `python -m tests.acceptance.run --system kaiten --json out.json`.
- В облаке kronto ходит через HTTPS-прокси песочницы или напрямую —
  как в продукте (`CONNECTOR_OUTBOUND_VIA_PROXY`).

Образец файла (значения придуманы; секреты настоящие — только в файле):

```json
{
  "kaiten": {
    "config": {"base_url": "https://krontoai.kaiten.ru"},
    "users": {
      "vetrov": {"token": "…"},
      "belova": {"token": "…"}
    },
    "extra": {"email_domain": "krontoai.ru"}
  }
}
```

## 1. Битрикс24 (система `bitrix24`, per_user, OAuth)

- **Что зарегистрировать.** Портал Битрикс24 (облако) `krontoai.bitrix24.ru`
  и в нём локальное приложение.
- **Цена и срок.** Есть бесплатный тариф: по странице тарифов —
  «неограниченно пользователей», диск 25 ГБ
  ([bitrix24.ru/prices](https://www.bitrix24.ru/prices/)). Платные: Базовый
  1 990 ₽/мес (5 пользователей), Стандартный 5 590 ₽ (50). Есть «Демо» —
  15 дней возможностей тарифа «Профессиональный», включается один раз на
  тарифах Бесплатный, Базовый, Стандартный
  ([справка](https://helpdesk.bitrix24.ru/open/27681014/)). Хватает
  бесплатного тарифа; платить не нужно.
- **Что нужно.** Домен — не нужен. Телефон и карта — на страницах не
  нашёл; регистрация идёт по почте или телефону владельца (проверить при
  регистрации).
- **Приложение.** «Приложения → Разработчикам → Другое → Локальное
  приложение» (инструкция — `docs/OAUTH-SETUP.md`): серверное, «только API»,
  права `disk` и `landing`, адрес возврата
  `https://stage.krontoai.ru/api/v1/connectors/oauth/callback`. Получите
  `client_id` и `client_secret`.
- **Сотрудники.** Пригласить шестерых по почте; в «Диске» раздела
  «Компания» создать папки зон и выдать права (см. `--plan`).
- **В файл.**

  ```json
  "bitrix24": {
    "config": {"portal": "https://krontoai.bitrix24.ru/", "client_id": "local.…"},
    "app": {"client_secret": "…"},
    "extra": {"email_domain": "krontoai.ru"}
  }
  ```

  Токены сотрудников — по одному на каждого, входом в браузере:
  `python -m tests.acceptance.oauth_login --system bitrix24 --login vetrov`
  (печатает адрес, ждёт `code=…` из адресной строки после входа).
  Модуль по умолчанию — «Диск компании» (`disk`).

## 2. Яндекс 360 (система `yandex360`, per_user, OAuth)

  проверить в кабинете. Придётся либо взять пробный/платный доступ на 10
  сотрудников, либо уточнить в «Демодоступе» вендора.
- **Что нужно.** Домен обязателен «в любом случае»
  ([справка](https://yandex.ru/support/business/domains.html)); `krontoai.ru`
  подходит, нужно подтвердить владение (DNS). Оплата предоплатой: пополнение
  баланса, карта не обязательна (карта — для автопополнения, счёт на
  юрлицо/ИП — по реквизитам). Телефон — не нашёл.
- **Приложение.** https://oauth.yandex.ru, рабочим аккаунтом, «Веб-сервисы»,
  права `cloud_api:disk.read`, `cloud_api:disk.info`, `wiki:read`, адрес
  возврата — как выше; ID организации — admin.yandex.ru → «Профиль
  организации» (`docs/OAUTH-SETUP.md`).
- **В файл.**

  ```json
  "yandex360": {
    "config": {"client_id": "…", "org_id": "…"},
    "app": {"client_secret": "…"},
    "extra": {"email_domain": "krontoai.ru"}
  }
  ```

  Токены каждого — `oauth_login --system yandex360 --login …`. Модуль по
  умолчанию — «Диск» (`disk`); общие диски и Вики — отдельными прогонами.

## 3. Google Workspace (система `gdrive`, organization)

- **Что зарегистрировать.** Google Workspace на `krontoai.ru`, проект в
  Google Cloud, сервисный аккаунт с делегированием на домен.
- **Цена и срок.** Пробный период 14 дней
  ([workspace.google.com/pricing](https://workspace.google.com/pricing):
  «Try Google Workspace for 14 days»). Лимит пользователей в пробном и
  нужна ли карта — вендор на странице не пишет; сторонние источники
  называют до 10 пользователей и ввод платёжных данных без списания до
  15-го дня ([googally](https://www.googally.com/blog/google-workspace-free-trial))
  — не подтверждено. Платные планы — на той же странице (цены там не
  выводятся без выбора региона).
- **Что нужно.** Свой домен (или покупка при регистрации), подтверждение
  владения доменом. **Риск:** продажа Google Workspace в РФ может быть
  недоступна ИП из России — я это не проверял; если регистрация не
  проходит, оставьте систему как «нет данных».
- **Ключи.** В Google Cloud: включить Google Drive API и Admin SDK API,
  создать сервисный аккаунт и JSON-ключ; в консоли Workspace
  («Безопасность → Доступ к данным → Управление API → Делегирование на
  уровне домена») вписать `client_id` ключа и три scope из
  `docs/CONNECTORS.md` (раздел «Google Диск»).
- **Разложить.** Общий диск на зону, участники — читатели зоны.
- **В файл.**

  ```json
  "gdrive": {
    "config": {"domains": "krontoai.ru", "admin_email": "vetrov@krontoai.ru"},
    "organization": {"service_account_key": "<весь JSON-ключ одной строкой>"},
    "extra": {"email_domain": "krontoai.ru"}
  }
  ```

## 4. VK WorkSpace (система `vk_workspace_disk`, per_user)

- **Что зарегистрировать.** Организацию в VK WorkSpace на домене
  `krontoai.ru`.
- **Цена и срок.** На [workspace.vk.ru](https://workspace.vk.ru/) —
  пробный период 14 дней за 1 ₽ на тарифы «Базовый» (309 ₽ за
  пользователя в месяц, до 300 человек) или «Расширенный» (499 ₽), кнопка
  «Протестировать». Бесплатный тариф для организаций больше 5 человек
  отключён с 01.11.2024 (сторонний источник — [Хабр](https://habr.com/en/news/753148)).
- **Что нужно.** Домен: подтверждение HTML-файлом, мета-тегом или
  DNS-записью. Работа по предоплате со счёта; нужно ли юрлицо для
  пробного периода и нужны ли телефон и карта (пробный стоит 1 ₽ —
  вероятно, оплата картой) — на странице не нашёл.
- **Ключи.** Каждому сотруднику: «Безопасность → Пароли для внешних
  приложений» с доступом «Облако» (WebDAV). Адрес WebDAV облака VK
  WorkSpace не задокументирован — в `docs/CONNECTORS.md` написано, что его
  вводит администратор; сверьте в кабинете (ожидаемый вид —
  `https://webdav.cloud.<почтовый домен>/`).
- **В файл.**

  ```json
  "vk_workspace_disk": {
    "config": {"server": "https://webdav.cloud.krontoai.ru/"},
    "users": {"vetrov": {"login": "vetrov@krontoai.ru", "password": "…"}},
    "extra": {"email_domain": "krontoai.ru"}
  }
  ```

  Диск у каждого свой: зоны раздаются общими папками; копия файла у
  каждого сотрудника — отдельный документ (сквозного id у WebDAV VK нет).

- **Цена и срок.** Бесплатный объём и тарифы на
  [cloud.mail.ru](https://cloud.mail.ru/) не нашёл (в выдаче страницы только
  навигация). Сторонний источник пишет, что WebDAV доступен только на
  платных тарифах ([comss.ru](https://www.comss.ru/page.php?id=7911)) — не
  подтверждено; проверить до оплаты.
- **Что нужно.** Телефон и карта — не нашёл. Регистрация на ИП для
  личного ящика невозможна — это личные кабинеты.
- **Ключи.** «Безопасность → Пароли для внешних приложений» → доступ
  «Облако» (по инструкциям rclone — «Полный доступ к Облаку (WebDAV)»);
  пароль показывается один раз.
- **В файл.**

  ```json
  "mailru_cloud": {
    "config": {"folders": ""},
    "users": {"vetrov": {"login": "…@mail.ru", "password": "…"}},
    "extra": {"email_domain": "mail.ru"}
  }
  ```

  У личных ящиков своих доменов нет; в режиме per_user kronto не
  сопоставляет почты (права берутся у каждого сотрудника отдельно), так что
  `email_domain` здесь ни на что не влияет.

## 11. Microsoft 365 (система `m365`, organization)

- **Что зарегистрировать.** Тенант Microsoft 365 (SharePoint и OneDrive) и
  регистрацию приложения в Entra ID.
- **Цена и срок.** Страницу бизнес-тарифов Microsoft не получил (ответ
  503). По документации kronto, подписку из России оформить нельзя
  (`docs/CONNECTORS.md`). Программа разработчиков — бесплатная подписка
  E5 для тех, у кого есть Visual Studio Professional/Enterprise или
  подходящая программа, продлевается, пока идёт разработка
  ([developer.microsoft.com](https://developer.microsoft.com/en-us/microsoft-365/dev-program));
  сторонний источник и FAQ называют 25 лицензий (24 тестовых пользователя
  и администратор) — число на странице вендора не нашёл.
- **Что нужно.** Для ИП из России, вероятно, недостижимо — решение:
  оставить систему как «нет данных». Домен: тенант получает
  `*.onmicrosoft.com`, `krontoai.ru` можно добавить как собственный.
- **Ключи.** Entra ID → «Регистрация приложений» → новое приложение →
  API permissions → Microsoft Graph → Application permissions
  `Sites.Read.All`, `Files.Read.All`, `User.Read.All`,
  `GroupMember.Read.All` → «Grant admin consent»; «Certificates & secrets» →
  новый секрет клиента (значение показывается один раз).
- **В файл.**

  ```json
  "m365": {
    "config": {"tenant_id": "…", "client_id": "…", "sites": ""},
    "organization": {"client_secret": "…"},
    "extra": {"email_domain": "krontoai.ru"}
  }
  ```
