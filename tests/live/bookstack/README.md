# Живой BookStack в Docker

Стенд для проверки вида `bookstack` (режим organization) на образе
`lscr.io/linuxserver/bookstack`: MariaDB, TLS-прокси nginx на 127.0.0.1 и
выдуманная компания — администратор `admin` (владелец API-токена),
`ivan`, `maria`, `petr`, `olga`. Все — в роли «Сотрудники» (только
«Access System API», без системного права просмотра); `ivan` ещё и в
«Редакторах» (просмотр всего по умолчанию), `maria` — в «Кадрах»,
`olga` — в «Авторах» (просмотр только своих страниц). Книги: «Общая»
(явное право «Сотрудникам», глава «Командировки», страница «Премии» с
переопределением только для «Кадров»), закрытая «Кадры» (только роль
«Кадры»; страница «Оргструктура» открыта всем «Сотрудникам», на
«Увольнения» — явный запрет «Сотрудникам»), «Проекты» без прав
содержимого (страница olga, страница с явным запретом). Два файла во
вложениях и одно вложение-ссылка. Тесты —
`tests/live/test_bookstack_live.py`; без переменных окружения они
пропускаются, в CI не идут.

Проверено 15.10.2026 на **BookStack v26.09.1**
(`lscr.io/linuxserver/bookstack:v26.09.1-ls288`, MariaDB 11.4.13,
nginx 1.31.6) — итоги внизу.

## Что нужно

- Docker, ~0,7 ГБ диска на образы, ~0,5 ГБ памяти.
- Postgres для тестов синхронизации — как у остального набора.
- При 429 от Docker Hub — `mirror.gcr.io/library/mariadb:11.4` и
  `mirror.gcr.io/library/nginx:1.31.6-alpine` и `docker tag` в имена из
  compose.yaml; BookStack берётся с `lscr.io`.

Ключ приложения `APP_KEY`, пароли MariaDB и пользователей
(`Kronto-Test-1`) — выдуманные, только для стенда на 127.0.0.1.
Администратор по умолчанию BookStack — `admin@admin.com` / `password`
(seed.py меняет почту на `admin@example.com`).

## Как поднять (≈2 минуты)

Все команды — из корня репозитория.

1. Сертификат стенда — как в `../nextcloud/README.md`, шаг 1
   (`DAV_TLS_DIR`, `DAV_STAND_CA`).

2. Запустить (порт 8460, другой — `BOOKSTACK_PORT`) и дождаться `200`
   (первый запуск создаёт базу, ~1 минута):

   ```bash
   docker compose -f tests/live/bookstack/compose.yaml up -d
   curl -s -o /dev/null -w '%{http_code}\n' --cacert ~/dav-tls/cert.pem https://127.0.0.1:8460/login
   ```

   `no-ipv6.sh` убирает из nginx образа `listen [::]`: в песочнице без
   IPv6 он иначе не стартует (на обычной машине не мешает).

3. Засеять компанию (только на чистом стенде). Скрипт входит
   администратором по умолчанию, выпускает его API-токен формой
   профиля (API токенов не выпускает), всё остальное делает через API и
   выпускает токены сотрудникам — для сверки; токены — в файл вне
   репозитория:

   ```bash
   BOOKSTACK_URL=https://127.0.0.1:8460/ \
     uv run python -m tests.live.bookstack.seed ~/bookstack-stand.json
   ```

4. Тесты:

   ```bash
   BOOKSTACK_URL=https://127.0.0.1:8460/ BOOKSTACK_TOKENS=~/bookstack-stand.json \
     uv run pytest tests/live/test_bookstack_live.py -q --no-cov
   ```

5. `cli connector-check` — как в `../webdav/README.md`, шаг 5, с
   `--stand https://127.0.0.1:8460 -- --kind bookstack --config
   base_url=https://127.0.0.1:8460/ --credential token_id=…
   --credential token_secret=…`. Пока вид не подключён в
   `default_registry`, команда его не знает — тест
   `connector_check_records_without_the_token` подменяет реестр.

6. Убрать стенд: `docker compose -f tests/live/bookstack/compose.yaml
   down -v` и `docker image rm` трёх образов.

## Что проверяют тесты

| Тест | Что доказывает |
|---|---|
| `listing_mirrors_bookstack_permissions` | Права по засеянной компании (`seed.EXPECTED`): общая роль с правом у каждого — вся компания; закрытая книга, переопределение страницы, явный запрет, «своё» — почты тех, кто видит; путь «Книга/Глава»; ссылка `/books/…/page/…`; вложение-ссылка не берётся |
| `rights_match_what_bookstack_shows_each_user` | **Сверка с самим BookStack**: страницы и вложения, которые каждый (admin, ivan, maria, petr, olga) получает по своему токену (`/api/pages`, `/api/attachments`), — ровно те, что адаптер ему отдал |
| `pages_and_files_are_fetched` | Страница — HTML из `/api/pages/{id}` с заголовком; файл вложения — байты из base64 |
| `wrong_token_is_an_auth_error` | Неверный токен → `AdapterAuthError("unauthorized")` |
| `employee_token_is_refused` | Токен сотрудника (API есть, управления пользователями и ролями нет) → `admin_required` |
| `sync_mirrors_access_and_follows_changes` | Полная синхронизация: сотрудник kronto видит ровно то, что BookStack; правка страницы → `updated`, страница в корзине → `removed`, выход maria из «Кадров» снимает доступ к «Зарплатам» и их вложению без переиндексации |
| `connector_check_records_without_the_token` | `cli connector-check --fetch 2 --record`: токена в записи нет |

Записанные со стенда ответы — фикстуры контракта
(`tests/connectors/fixtures/bookstack/live`,
`tests/connectors/test_bookstack_live_fixtures.py`).

## Итоги 15.10.2026

- 7 из 7 тестов (≈75 секунд: BookStack на стенде отвечает ≈0,2 с на
  запрос, листинг стенда — 34 запроса).
- Права адаптера совпали с тем, что BookStack отдаёт каждому из пяти
  пользователей по его токену, во всех девяти случаях, включая
  страницу, открытую при закрытой книге («Оргструктура»), явный запрет,
  который перевешивает право «по умолчанию» другой роли («Смета» у
  ivan), и «своё» («Заметки автора» у olga).
- Лимит API (180 запросов в минуту) срабатывает уже на прогоне тестов:
  429 с `Retry-After` в секундах до сброса окна — клиент ждёт и
  повторяет, запуск не падает.
- В списке пользователей есть гость (`guest@example.com`, роль Public):
  он не учитывается ни в правах, ни в «всех пользователях».
- id книг, глав и страниц в v26 идут одной последовательностью; адаптер
  на это не опирается (ключи — с типом: `page:`, `attachment:`).

## Что стенд не проверяет

- Версии до v26 (права содержимого и роли есть в API с v23.x — точную
  версию не сверяли; алгоритм прав тот же с v23.01), живьём не открывали.
- Вход через LDAP/SAML/OIDC: роли из внешних групп назначаются при
  входе — API показывает уже назначенные, это проверено только кодом.
- Полки (на права книг не влияют) и черновики (видны только автору —
  пропускаются; на стенде их нет).
- Большую установку: на каждую страницу — запрос прав, при лимите 180 в
  минуту запуск на 1000 страниц займёт ≈10–15 минут.
