# Замеры качества (eval)

Здесь инструменты, которыми ML проверяет поиск и ответы ассистента.
Правило одно: **сначала замер, потом изменение.** Любую настройку —
нарезку, порог, промпт, модель — меняем только если прогон на одних и
тех же вопросах показал разницу вне шума. Все решения и числа —
[`docs/ml-report.md`](../docs/ml-report.md), простыми словами —
[`docs/ml-summary.md`](../docs/ml-summary.md).

## Быстрый старт

```bash
uv sync --dev
uv pip install -r eval/requirements.txt    # numpy, извлечение docx/pdf
```

Ключи Яндекса — в `.env`, как у бэкенда: `YC_FOLDER_ID`, `YC_API_KEY`.
Команды запускаются из корня репозитория: `python -m eval.<инструмент>`.

Бесплатный первый прогон — поиск по своим документам на своём наборе
вопросов (платны только эмбеддинги, копейки, и они кэшируются):

```bash
python -m eval.bench --corpus путь/к/документам --dataset eval/private/golden.csv \
    --split dev --retriever vector
```

## Что считается «продуктом»

Значения по умолчанию у `offline_e2e` и `judge` — те, что стоят в
продукте: прогон без флагов меряет то же, что увидит сотрудник. У
`bench` по умолчанию BM25 (он работает без ключей) — для продуктового
поиска нужен `--retriever vector`.

| Настройка | Значение | Флаг, чтобы поменять |
|---|---|---|
| модель ответа | Alice AI LLM Flash, OpenAI-совместимый API, температура 0 | `--model`, `--api`, `--temperature` (`offline_e2e`) |
| эмбеддинги | `text-embeddings-v2`, 768 | `--embedding-model`, `--embedding-dim` |
| нарезка | 400 токенов, перекрытие 50, крошки с названием документа | `--chunk-tokens`, `--overlap-tokens`; только в `bench`: `--no-crumbs`, `--crumbs-without-title` |
| поиск | только вектор | `--retriever hybrid --weights 1.0,0.5` (в `bench` ещё `bm25`) |
| порог отказа | 0,51 (косинусное расстояние) | `--max-distance` (`offline_e2e`) |
| фрагментов в ответ | 5, до 3 000 токенов | `--limit`, `--context-tokens` (`offline_e2e`) |
| промпт | `faq-v2.5` | — (версия в `src/corp_ed/prompts/faq.py`) |
| ответа в документах нет | общий ответ с пометкой | `--not-found strict` — только отказ |

Про последнюю строку: в продукте с 28.09 новая компания по умолчанию
получает честный отказ, общий ответ включает команда. Стенд по умолчанию
меряет общий ответ, чтобы видеть и его качество; отказ — `--not-found
strict`.

Константы — в начале [`yandex.py`](yandex.py).

## Наборы вопросов

### Золотой — `eval/private/golden.csv`

Главный набор: по нему принимаются решения. 52 вопроса, проверенных
людьми, 20 из них написаны людьми. В git не попадает: `eval/private/`
закрыт `.gitignore`, репозиторий публичный.

```
id,question,expected_answer,expected_material,expected_section,in_corpus,type,level,evidence,author,split
```

- `type` — `fact`, `procedure`, `negation` (ложная посылка или «нельзя
  ли…»), `comparison`, `out_of_corpus`.
- `evidence` — дословная цитата с ответом. Правильным считается фрагмент,
  где есть не меньше 80 % пар соседних слов цитаты. Без цитаты —
  любой фрагмент нужного раздела.
- `expected_section` — начало заголовка: `3.1` совпадёт с
  «3.1. Продолжительность», но не с «3.12».
- `split` — **dev (33)** для настройки и **holdout (19)** для финальной
  проверки. Разбиение делается один раз (`python -m eval.datasets split`).
  Без `--split holdout` инструменты holdout не берут. **Holdout
  открывается один раз, на финальном прогоне.** Новые вопросы — только
  в dev.
- Вопросы из интервью сотрудников — с `id` на `iv`.

Как писать вопросы — [`docs/ml-golden-guide.md`](../docs/ml-golden-guide.md).
Пример формата — [`golden.example.csv`](golden.example.csv). Проверка
состава: `python -m eval.datasets eval/private/golden.csv`.

### Серебряный — синтетика

Модель пишет вопросы к случайным фрагментам корпуса:

```bash
python -m eval.generate_silver --corpus путь/к/документам --n-chunks 120
```

Эталон — цитата, а не номер фрагмента: номера меняются при каждой
перенарезке. Фильтры выкидывают вопросы, которые копируют текст, и
повторы. **Перекос:** синтетические вопросы лексически близки к тексту,
поэтому полнотекстовый поиск на них выглядит сильнее, чем на живых.
Серебряный годится, чтобы сравнивать нарезки между собой; решения —
только по золотому.

## Инструменты

| Команда | Что делает | Платно |
|---|---|---|
| `eval.bench` | поиск без бэкенда: режет корпус, ищет в памяти вектором, BM25 или гибридом; Hit@K, MRR с 95 % CI | эмбеддинги (копейки, кэш) |
| `eval.offline_e2e` | весь путь ответа без бэкенда: поиск → порог → контекст → промпт → модель | да, ≈ 0,2 ₽ за ответ; `--dry-run` — бесплатно |
| `eval.judge` | модель-судья: верно / частично / неверно по эталону; `--calibrate` — согласие с ручной разметкой | да |
| `eval.compare` | разница двух прогонов на одних вопросах: 95 % CI и p-value | нет |
| `eval.threshold` | распределения расстояний «по документам / вне», кандидаты порога | нет |
| `eval.run_eval` | те же замеры через HTTP API живого бэкенда | как у бэкенда |
| `eval.datasets` | проверка состава набора, однократное разбиение dev / holdout | нет |
| `eval.generate_silver` | серебряный набор | да |
| `eval.gaps_eval` | проверка отчёта о пробелах: убираем документы, вопросы по ним — настоящие пробелы | эмбеддинги |
| `eval.alice_compare` | сравнение с Алисой AI для бизнеса: бланк, слепые файлы для судьи, отчёт | судья |
| `eval.probe_embedding_limit` | проба эмбеддера: лимит входа, размерности, символов на токен | копейки |
| `eval.bench_reranker` | задержка реранкера на CPU (нужен `sentence-transformers`) | нет |

У каждого инструмента `--help` с полным списком флагов.

## Типовые сценарии

**1. Поменял что-то в поиске — стало лучше?**

```bash
python -m eval.bench ... --split dev --retriever vector --config base
python -m eval.bench ... --split dev --retriever vector --config new <флаг изменения>
python -m eval.compare <…_base_bench.csv> <…_new_bench.csv> --metric rr      # и --metric hit@5
```

**2. Поменял промпт, порог или число фрагментов — ответы лучше?**

```bash
python -m eval.offline_e2e --corpus … --dataset eval/private/golden.csv --split dev --config base
python -m eval.offline_e2e … --config new <флаг изменения>
python -m eval.judge --results <…_base_e2e.csv>        # и для new
python -m eval.compare <…_base_e2e_judged.csv> <…_new_e2e_judged.csv> --metric judge_correct
```

Сравнивать ответы можно только оценёнными **одной и той же** моделью
судьи.

**3. Попадёт ли нужный текст к модели — бесплатно.** `--dry-run` не
вызывает модель: считает поиск, контекст и колонку
`evidence_in_context` — дошла ли цитата эталона до модели.

**4. Порог отказа.** Прогнать поиск на золотом наборе (там есть вопросы
вне документов), затем `python -m eval.threshold <…_bench.csv>`. Скрипт
предлагает 2–3 кандидата. Окончательный выбор — по ответам (сценарий 2):
по метрикам поиска порог выглядит лучше, чем работает на деле.

**5. Через живой бэкенд.** `python -m eval.run_eval retrieval|e2e|score`.
Нужны `CORP_ED_BASE_URL` и `CORP_ED_TOKEN` (или `CORP_ED_COMPANY` +
`CORP_ED_EMAIL` + `CORP_ED_PASSWORD`; для `/faq/search` — администратор).
`--config` — только имя в отчёте, на бэкенде скрипт ничего не меняет.

**6. Сравнение с Алисой AI для бизнеса.** Ответы Алисы собирает человек
(API у продукта нет) — протокол в
[`docs/ml-alice-protocol.md`](../docs/ml-alice-protocol.md):

```bash
python -m eval.alice_compare blind --ours <наши _e2e.csv …> --alice eval/private/alice_answers.csv --out-dir eval/private/results/alice
python -m eval.judge --results eval/private/results/alice/<дата>_ours-blind_e2e.csv --model aliceai-llm    # и alice-blind
python -m eval.alice_compare report --ours <…ours-blind_e2e_judged.csv> --alice <…alice-blind_e2e_judged.csv>
```

`blind` оставляет судье только вопрос, эталон и ответ без оформления —
он не знает, чей это ответ.

## Как читать результаты

Каждый прогон пишет CSV по вопросам и строку в `summary.csv` рядом.
Результаты по публичным данным — в `eval/results/` (коммитятся); всё, что
содержит золотой набор или ответы по нему, — в `eval/private/results/`
(флаг `--out`).

- **«Лучше»** — только если 95 % интервал разницы не содержит ноль **и**
  p < 0,05. Иначе — шум, настройку не меняем. На 26–33 вопросах
  различимы только крупные эффекты.
- **Hit@5** — нужный фрагмент среди 5 найденных; **MRR** — насколько
  высоко он стоит (1 — первым, 0,5 — вторым).
- **F1 отказа** — насколько точно система отвечает на вопросы по
  документам и отказывает на остальных.
- **Судья** откалиброван 26.09 по 39 ручным оценкам: совпадение 36 из 38,
  каппа Коэна 0,89. Он строже человека, поэтому его доля верных — нижняя
  граница. Без выдержек (как в сравнении с Алисой) судья ошибается чаще —
  такие вердикты проверять.

## Правила

- Одно изменение за эксперимент. Температура 0.
- Holdout не открывать до финального прогона.
- Прогон дороже 300 ₽ — сначала смета.
- Не запускать два стенда одновременно: квота эмбеддингов — 10 запросов
  в секунду на каталог, клиент держит 8.
- Документы клиентов и живые вопросы — только в `eval/private/`.

| Что | Итог | Где |
